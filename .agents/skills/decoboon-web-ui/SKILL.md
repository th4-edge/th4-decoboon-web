# 装得清 Web V3 UI 与交互智能体

## 核心判断

> 界面的专业度不来自装饰，来自**层级、对齐、留白、一致性、状态完整**五件事；任何一项缺失，页面就是业余的。

## 不可违反的边界

1. **未渲染不得交付**：设计结论必须来自真实浏览器三档截图。
2. **只有一套设计语言**：`src/styles/tokens.scss` 是唯一视觉真源，页面禁止裸色值/裸字号/裸圆角。
3. **正文字号 ≥13px**，辅助信息 ≥12px；`$font-micro` 仅限角标、头像字母。
4. **状态不能只靠颜色**：状态 = 文字 + 颜色 + 位置（必要时图标）。
5. **一个页面只有一个主行动**。
6. **可访问性不换视觉**：禁止 `outline: none`；键盘可达、焦点可见、对比度达 AA。
7. **不绕过组件层**：禁止页面自造卡片/状态标签/抽屉/空态/错误态。
8. **不跳过批判循环**：交付前至少两轮「渲染 → 截图 → 按反模式清单批判 → 修正 → 再渲染」。

## 开始前必须读取

1. `AGENTS.md`、`docs/product/WEB-DESIGN-SYSTEM.md`、`docs/product/WEB-COMPONENT-SPEC.md`、`docs/product/WEB-PAGE-DELIVERY-GATE.md`。
2. `src/styles/tokens.scss`（实际变量）。
3. `decoboon-web-product` 的冻结迭代包（页面类型、唯一主行动、信息优先级）。
4. App 端同一业务对象页面，确认跨端信息口径一致。

## 三步设计流程

### D1 设计意图（动笔前冻结七问）
页面类型（决策页/行动队列/对象详情/专业列表/表单抽屉）｜谁在什么状态下打开｜第一个要得到的答案｜唯一主行动｜信息优先级（≤3 层）｜与 App 的差异｜七类状态。

### D2 构图与状态
1. 选定构图模板，确定栅格与区块顺序。
2. 定义全部状态：正常 / 加载 / 失败 / 真实为空 / 无权限 / 会话过期 / 长内容（含极端数值）。
3. 定义交互时序：动作 → 即时反馈 → 处理中 → 结果 → 失败恢复。
4. 列出复用组件；新增必须说明现有组件为何不满足。

### D3 视觉批判循环（≥2 轮）
渲染 → 三档截图 → 按反模式清单逐条批判 → 修正 → 再渲染，直到量规通过。

## 评审量规（任一维度 <3 不得交付；主链页平均 ≥3.5）

`信息层级 / 对齐与留白 / 一致性与规范 / 状态完整 / 可访问性 / 中文与数值排版 / 宽屏效率 / 交互反馈`（0–4 分）。

## 输出契约

```text
页面 | 设计意图七问 | 构图与栅格 | 七类状态 | 复用/新增组件
三档截图路径 | 批判轮次与修正项 | 量规得分 | 未解决项与原因 | 结论
```
