# 装得清 Web V3 组件规范

> 状态：V3 重建。组件是「页面唯一实现路径」：页面不得绕过组件层自造同类元素。

## 1. 组件来源

| 来源 | 使用方式 |
| --- | --- |
| Element Plus | 基础控件（表单、表格、分页、弹层、消息），按需引入 |
| `src/components` | 装得清业务组件（状态、金额、空态、错误态、对象头等） |
| 页面私有 | 仅限该页且无复用价值；一旦第二处使用必须上收 |

禁止整库导入 UI 库；新增依赖必须评估体积。

## 2. 已登记组件（V3 基线）

| 组件 | 职责 | 关键约束 |
| --- | --- | --- |
| `BrandMark`（规划） | 品牌标记 | 与 App / Admin / Site 同源，禁止另存图片 |
| `StatusTag`（规划） | 业务状态标签 | 文字 + 颜色 + 位置；色值来自 `$status-*` |
| `MoneyText`（规划） | 金额展示 | 由服务端返回；缺失时显示「暂不可确认」 |
| `CostIncompleteValue`（规划） | 成本未完整占位 | 禁止展示 0 成本或伪利润 |
| `EmptyState`（规划） | 真实为空 | 必须给出下一步，不得与「加载失败」混用 |
| `ErrorState`（规划） | 加载失败 | 表达「暂不可确认」并提供重试 |
| `NoPermissionState`（规划） | 无权限 | 不泄露对象名称与金额 |
| `ObjectHeader`（规划） | 对象详情头部 | 状态、责任人、下一动作、asOf |

> 规划组件在实现前，对应能力不得用页面内自定义元素替代交付。

## 3. 状态完整性（每个数据组件必须实现）

正常 / 加载 / 失败 / 真实为空 / 无权限 / 会话过期 / 长内容。

## 4. 新增流程

1. 说明现有组件为何不满足（引用具体组件与限制）。
2. 定义 props / emits / 状态清单 / 可访问性行为。
3. 在真实浏览器三档分辨率验证后登记到本文件。
4. 未登记不得在第二个页面使用。
