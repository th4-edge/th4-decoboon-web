# 装得清 Web V3 产品宪章

> 状态：V3 重建基线（2026-10-06）
> 业务事实源：全局技能 `zhuangdeqing-business` 与规范业务库。本文只定义产品定位与边界，不定义业务规则。

## 1. 产品定位

装得清 Web 是**家装企业的经营工作台**，服务两类核心场景：

1. **老板经营决策**：看经营、看项目、看人效、看风险、看资金与利润。
2. **员工岗位执行**：围绕同一业务事实完成本人职责范围内的下一步，以及 App 不擅长的批量维护、对账、排期与经营分析。

> Web 不是小程序的放大版，也不是传统 ERP 的字段集合。

## 2. 三类使用者与目标

| 使用者 | 打开 Web 的第一问题 | V3 必须给出的答案 |
| --- | --- | --- |
| 企业负责人（Boss） | 这家公司现在健康吗？哪里要出事？ | 经营结论、风险项、待决策事项与下钻入口 |
| 店长 / 团队负责人 | 我这摊子今天卡在哪、谁在等我？ | 门店/团队待办、超期项、人员负荷与交接状态 |
| 岗位员工 | 我这一步该做什么、做完交给谁？ | 当前对象、唯一主行动、交接去向与完成条件 |

## 3. 三个壳层（冻结）

### 3.1 经营管控层（Boss）
一级导航固定六项：`经营总览 / 业务分析 / 项目监管 / 财务经营 / 组织效能 / 风险中心`。
以决策、风险和异常优先，不承载普通员工的批量录入；需要处理具体业务时下钻到共享对象页。

### 3.2 员工岗位执行层
一级导航：`今日主线 / 客户与设计 / 报价与合同 / 项目工地 / 商务财务`，按角色能力动态过滤。
角色工作台优先，专业列表作为深链接与批量操作入口。

### 3.3 共享对象层
所有角色共享统一的业务对象详情（客户 / 房屋 / 设计 / 报价 / 合同 / 项目 / 工地 / 变更 / 验收 / 账务）。
同一对象在不同角色下只允许**投影差异**（字段可见性、字段顺序、动作集合），不允许口径差异。

## 4. 产品原则

1. **一个业务事实源**：同一事实在 App 与 Web 必须一致；不一致建立 `DEF-*` 登记，禁止单端改文案掩盖。
2. **下一步优先**：页面先回答「现在发生了什么、下一步是什么、谁负责、卡在哪里」，再提供全量数据浏览。
3. **可完成状态由事实推导**：完成度只能来自当前租户真实领域对象；接口异常表达为「暂不可确认」。
4. **金额可信**：金额、成本、利润、计数一律由服务端返回；成本不完整时不展示利润。
5. **不做无权限的可见性**：菜单、路由、接口三层一致；前端隐藏不等于授权。
6. **AI 受控**：AI 辅助只在明确边界内提供建议，不替用户做金额、权限和终态确认。

## 5. 明确不做（V3 范围外）

- 不做 App 已有能力的重复实现，除非 Web 有批量或对账效率优势。
- 不做第二套业务状态机或前端本地状态派生。
- 不做多租户之外的跨企业数据聚合（平台运营域除外，不属于本工程范围）。
- 不在未冻结业务口径的页面上展示任何金额、比例或完成度。
