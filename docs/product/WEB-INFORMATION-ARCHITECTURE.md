# 装得清 Web V3 信息架构

> 状态：V3 重建基线。壳层归属一旦冻结，页面不得在两个壳层重复实现。

## 1. 路由骨架

```text
/login                      登录（唯一公开入口）
/workbench                  角色工作台入口（按角色解析壳层）
  ├─ Boss     → 经营管控中心（6 个一级导航）
  └─ 其他岗位 → 岗位工作台（按能力过滤一级导航）
/forbidden                  无权限（保留返回路径）
/*                          404（区分「不存在」与「未接入」）
```

角色到壳层的解析集中在 `src/roles/permission.ts`；页面不得自行判断角色字符串。

## 2. 页面类型（只允许五类）

| 类型 | 用途 | 唯一主行动 |
| --- | --- | --- |
| 决策页 | 老板判断经营健康与风险 | 下钻到风险/事实 |
| 行动队列 | 岗位处理今日待办 | 处理当前事项 |
| 对象详情 | 单个业务对象全貌与操作 | 推进到下一状态 |
| 专业列表 | 批量查询、筛选、导出、对账 | 查询/批量操作 |
| 表单抽屉 | 新增/编辑/确认 | 提交 |

## 3. 信息优先级（每页 ≤3 层）

1. **结论层**：状态、金额/数量、风险、完成度（带口径与 asOf）。
2. **行动层**：下一步、责任人、阻断项、交接对象。
3. **证据层**：明细、留痕、附件、历史。

## 4. 深链接与刷新

- 所有业务对象详情必须有稳定 URL（含业务 ID）。
- 直开、刷新、会话过期三种情况必须正确降级：未登录 → 登录后回到原地址；无权限 → `/forbidden`；对象不存在 → 明确空态，不泄露对象名称。

## 5. 断点续接

- 列表页的筛选、分页、排序必须可回退（返回时恢复）。
- 从 Boss 下钻到对象后，「返回」必须回到原筛选上下文。

## 6. 跨端差异

Web 必须比 App 更强的地方：批量操作、多列对账、导出、排期、长表格、经营分析、宽屏信息密度。
Web 必须与 App 一致的地方：状态口径、金额口径、权限结论、完成条件、责任人。
