## 1. 页面定位

「待我跟进」不是客户通讯录，也不是客户 360 的替代页面。它是设计师在预约量房前的到期跟进队列：

```text
服务端到期事实
-> 左栏客户/房屋队列
-> 中栏选中客户/房屋事实
-> 右栏原因、唯一主行动、完成回读和下一接棒
```

页面必须让设计师打开后直接知道：

1. 今天先联系谁；
2. 这次跟进对应的客户和可选房屋是什么；
3. 服务端给出的风险原因和下一步是什么；
4. 保存跟进后系统会回读哪些事实；
5. 是否进入量房或其他客户经营路径。

## 2. 真实业务场景

### 场景 A：设计师兼业务员的一人主链

- 使用人：设计师小周，同时负责首联和设计。
- 触发事件：上午打开工作台，昨日预约的客户需要今天回访，另一个客户已逾期 2 天。
- 当前动作：进入「待我跟进」，先处理逾期客户，再处理今日客户。
- 系统下一步：左栏按逾期、今日、3 天内、未安排排序；中栏显示客户、房屋和最近跟进；右栏给出风险原因和「写跟进」主行动。
- 异常处理：客户电话不可用或跟进保存失败时保留输入和上下文，不伪造成已完成。
- 验收结果：保存后客户、跟进记录和队列回读一致；页面不自动切换客户，由用户显式选择下一项。

### 场景 B：多房屋客户

- 使用人：设计师陈工，客户准备同时比较两套房屋。
- 触发事件：客户已建档，但没有明确哪套房屋需要安排量房。
- 当前动作：从队列选择客户，在中栏显式选择房屋，再写跟进或去待我量房。
- 系统下一步：右栏提示多房屋必须显式选择 `activeProperty`；未选择时不默认第一套。
- 异常处理：没有房屋时提供建立房屋档案路径，仍可先写跟进但不伪造量房锚点。
- 验收结果：刷新、返回和深链接后恢复 `customerId + activePropertyId`，不同入口看到同一客户事实一致。

## 3. 入站与排序

入站客户范围：

- 当前设计师数据范围内本人负责或指派给本人设计的客户；
- 客户阶段仅限 `New` / `Following`；
- `Dormant`、`Lost` 及其他已完成量房后的阶段不进入本队列；
- 队列项为逾期、今日、3 天内或未安排下一次跟进。

排序：

1. 逾期；
2. 今日；
3. 3 天内；
4. 未安排；
5. 同组按服务端 `nextFollowAt` 和稳定客户 ID 排序。

## 4. 页面信息融合与起点边界

待我跟进和客户 360 都是合法起点，不是必须互相跳转的前后步骤。待我跟进页面必须自己承载本起点的全部关键操作：

1. 客户 Hero 融合姓名、电话、来源、小区、面积、预算、负责人、设计师、阶段、风险、客户评级、微信/到店、标签和画像摘要。
2. 客户评级直接在 Hero 展示，使用 A/B/C 语义色；未计算时显示“待评估”。
3. 画像在本页弹出编辑，不强制去客户 360。
4. 房屋与最近沟通上下排列，保留完整信息密度，不为了首屏强行左右挤压。
5. 右侧只保留“本次跟进建议 + 客户操作”两个视觉块；关键操作优先可见，允许在 1280 以下按上下顺序延展。
6. 主操作用品牌实色；沟通用品牌浅底；事实记录用绿/橙语义色；完整档案用中性次级色；休眠用橙色提醒；恢复用绿色。
7. 写跟进、基础资料、画像、微信、休眠统一使用右侧抽屉，抽屉内按上下文、录入区、结果说明、主行动组织。
8. 待跟进的核心预约动作统一命名为“预约量房”；没有房屋时在预约抽屉内建立房屋，预约成功后自动进入待我量房并定位本次客户和房屋。
9. 待我跟进、待我量房复用同一套休眠服务与右抽屉；业务员、店长、企业负责人和设计师可设置，未结束合同由服务端阻断；未来量房预约允许保留。
8. 客户基础资料在本页可直接编辑；画像“主要顾虑”使用可见 checkbox 多选，参考 App 画像维护页。

## 5. 客户上下文与动作设计

中栏客户上下文按 App 客户 360 的高频信息对齐：

- 基本信息：电话、来源、小区/地址、面积、预算、等级、负责人、负责设计师；
- 关系事实：是否已加微信、微信号、到店次数、最近到店时间；
- 客户画像：装修目的、房屋状况、开工窗口、风格、环保、家庭结构、付款、竞品对比、关注点；
- 客户标签：系统标签与人工标签；
- 最近沟通：跟进记录、方式、时间、下次联系时间。

右栏动作按设计师工作语言组织：

| 动作 | 使用场景 | 权限 |
| --- | --- | --- |
| 写跟进 | 本次沟通后记录结果和下一次联系时间 | 当前可见客户的设计师 |
| 打电话 | 直接联系客户 | 当前可见客户 |
| 记录加微信 / 更新微信 | 客户已加微信时登记或修改微信号 | 当前可见客户 |
| 记录到店 | 客户到店后登记一次 | 当前可见客户 |
| 客户 360 | 查看完整资料、房屋和业务进展 | 当前可见客户 |
| 预约量房 | 选择已有房屋或建立新房屋，并约定上门量房时间 | 按房屋与量房权限 |
| 设为休眠 / 恢复跟进 | 客户暂时不需要继续跟进 | 业务员、店长、企业负责人和设计师 |

Designer 角色在待我跟进和待我量房中可生成休眠入口，但客户范围、状态、合同与状态门禁仍由服务端最终校验；未来量房预约不再阻断。所有动作文案描述“何时使用、会产生什么结果”，不展示“服务端、主链、回读”等内部术语。

## 6. 三栏职责

| 栏位 | 内容 | 禁止 |
| --- | --- | --- |
| 左栏 | 客户、房屋摘要、阶段、风险、下次跟进、筛选数量 | 只列客户不表达房屋；伪造房屋 |
| 中栏 | 客户身份、阶段、风险、联系人、最近跟进、房屋、下一步事实 | 复制右栏主行动；默认第一套房屋 |
| 右栏 | 为什么处理、唯一主行动、阻断原因、完成回读、其他合法动作、下一接棒 | 前端自算状态；自动切换客户 |

## 7. 主行动与回读

主行动：`写跟进`（`customer/customer-follow/save`）。

前置条件：

- 客户在当前设计师可见范围内；
- 跟进内容非空；
- 未处于休眠、流失等不允许的状态。

完成后的回读：

- Customer；
- CustomerFollow；
- Property（如本次创建或选择房屋）；
- 工作台队列；
- 客户风险、下一次跟进时间和主链动作。

任一回读失败显示「部分数据暂不可确认」，保留已成功事实与恢复路径。
