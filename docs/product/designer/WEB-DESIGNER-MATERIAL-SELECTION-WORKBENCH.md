## 1. 真实使用场景

### 场景 A · 现场确认后集中代录

- 使用人：设计师。
- 触发事件：客户现场或逐项沟通已确认颜色、规格、品牌、工艺，设计师回到办公室集中录入。
- 当前动作：在项目交付菜单打开主材选材，先看哪些在跑项目尚未完成选材，再进入具体项目逐项维护。
- 系统下一步：保存即“已选材（现场确认）”；交付后材料计划进入待财务下单，由财务决定供应商、价格和数量。
- 异常处理：材料分项读取失败时保留项目和队列，显示“部分数据暂不可确认”；已进入采购的分项禁止直接改选材，引导发起增减项。

### 场景 B · 已进入采购后的换材

- 使用人：设计师。
- 触发事件：客户要求更换已经下单或到场的材料。
- 当前动作：设计师在选材队列看到“有已采购”标记，进入分项只查看锁定原因。
- 系统下一步：不允许在选材页改价格、数量或换材，必须进入增减项流程。
- 异常处理：若项目合同没有主材分项，页面显示“合同主材分项未配置”，不把空数组伪装成完成。

## 2. 设计意图冻结（D1）

| 问题 | 结论 |
| --- | --- |
| 页面类型 | 项目交付行动队列，不是项目 CRUD 列表 |
| 使用角色与状态 | 设计师/企业负责人/店长/财务，在需要推进主材选材或财务下单前打开 |
| 首屏要回答的问题 | 当前数据范围内还有哪些项目没完成选材，各自缺口多少，哪一项已进入采购 |
| 唯一主行动 | 选中项目后进入逐项工作区，现场代录选材并交付财务下单 |
| 信息优先级 | ① 待选材项目与缺口；② 房屋/项目上下文和材料锁定；③ 分项明细预览与边界说明 |
| 与 App 差异 | App 以单项目单项录入为主；Web 增加跨项目队列、筛选、项目切换和批量查找能力，交互形态不复刻 App |
| 不做什么 | 不显示客户姓名；不在这里改报价/合同/成本/数量；不代替客户登录确认；不直接下单 |

## 3. 页面结构

1. 顶部结论区：待完成项目数、待选材分项数、已进入采购需走增减项的分项数。
2. 左栏项目队列：搜索项目/小区/门牌；筛选全部、未发起、选材中、有已采购；内部滚动。
3. 中栏对象工作面：唯一项目 Hero、选材进度、当前下一步、待选材/已选材/已交付/已采购四项事实、分项预览。
4. 右栏业务边界：现场代录口径、采购锁定与增减项边界、维护/只读角色、最近更新时间。

对象内逐项工作区继续由 `/designer/projects/:projectId/materials` 承接，列表页不复制编辑表单。

## 4. 权限与动作边界

| 动作 | Designer | Boss | StoreManager | Finance | Pm / TeamLeader / Marketer |
| --- | --- | --- | --- | --- | --- |
| 查看队列 | 本人数据范围 | 企业数据范围 | 门店数据范围 | 财务数据范围 | 不进入写入工作台 |
| 保存/交付选材 | 允许 | 允许 | 允许 | 允许 | 只读且不暴露写入入口 |
| 改价/改量/换材 | 不允许 | 不允许 | 不允许 | 不允许 | 不允许 |
| 下单与供应商/价格/数量 | 不允许 | 按财务边界 | 按现状 | 财务动作 | 不允许 |

- 选材保存不改变报价、合同、成本、材料计划数量、采购与库存。
- 材料计划进入采购后锁定制程；换材走增减项。
- 前端菜单、路由和按钮只做可见性，最终以服务端 Provider 校验为准。

## 5. 页面状态

| 状态 | 页面行为 |
| --- | --- |
| loading | 队列和分项分别显示骨架，不显示旧值冒充当前值 |
| empty | 数据范围内没有待选材项目时说明原因，不显示 0 成本或伪造完成 |
| error | 队列 Provider 失败时整页显示“暂不可确认”和重新加载 |
| partial | 队列成功、分项失败时保留项目摘要，标出未加载分项并提供重新读取 |
| unauthorized | 路由角色与服务端权限拦截，不渲染写入入口 |
| expired | 沿用全局 401/会话过期处理，路由回登录并保留回跳地址 |
| stale | 详情保存后重新读取当前选材事实与材料计划锁定状态 |
| success | 保存/交付后回读 materialSelection、materialPlan、project、workbenchQueue 等范围 |
