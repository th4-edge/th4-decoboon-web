# 客户 360 · 编辑能力与 Tab 展示丰富（详细规划）

> 状态：`PLAN`（待确认 §5 决策后实施）
> 范围：设计师「我的客户 → 客户 360」页；不改业务对象与状态机
> 事实源：BR-001 客户—房屋—报价—项目主链、DEC-002 六条冻结映射、SCN-014、AGENTS 数据删除与统计门禁

---

## 1. 结论摘要

1. **方向一（编辑）**：客户基本信息、客户画像、房屋新增/编辑 —— **后端 Provider 全部已存在**，只缺前端表单；
   **房屋删除后端没有 Provider**，而且「数据删除」在 AGENTS 里属于高风险动作，需要先定门禁规则再建。
2. **方向二（Tab 丰富）**：三个 Tab 现在都只做到「一行摘要」，信息密度不足。
   本稿给出方案/报价/项目三张 Tab 的**字段级规划、状态口径与动作边界**，供确认后实施。

## 2. 方向一：对象编辑能力

### 2.1 能力矩阵（已核实）

| 能力 | 后端 Provider | 前端 API | 结论 |
| --- | --- | --- | --- |
| 客户基本信息编辑 | `customer/customer/update` ✅ 存在 | 缺 | 可直接接 |
| 客户画像编辑 | `customer/customer-portrait/save` ✅ 存在 | 缺 | 可直接接 |
| 房屋新增 | `property/property/save` ✅ 存在 | `propertyApi.saveProperty` ✅ | 可直接接 |
| 房屋编辑 | `property/property/update` ✅ 存在 | `propertyApi.updateProperty` ✅ | 可直接接 |
| **房屋删除** | **无 Provider** ❌ | 缺 | **需新建 + 先定门禁** |

> 房屋删除是本次唯一需要新增后端能力的地方，而且是**数据删除**：按 AGENTS 必须走备份、全量验证、可回滚与用户确认。

### 2.2 客户基本信息编辑（规格）

**Provider**：`customer/customer/update`（`customerId` 必填）

| 字段 | 类型 | 校验 | 说明 |
| --- | --- | --- | --- |
| 姓名 | 文本 | 必填、≤32 | |
| 手机号 | 文本 | 11 位、唯一性由服务端裁决 | 冲突时展示服务端原文 |
| 性别 | 枚举 | 选填 | 需补前端枚举字典 |
| 客户来源 | 枚举 `Lead/Referral/WalkIn/OldCustomer/Video/Other/BatchPhone` | 选填 | |
| 小区 | 文本 | 选填、≤128 | |
| 详细地址 | 文本 | 选填、≤256 | |
| 面积 | 数值 | 选填、>0 | 单位 ㎡ |
| 预算 | 金额 | 选填、≥0 | 金额可见，**不涉及成本/利润** |
| 备注 | 长文本 | 选填 | |
| 负责人 | 员工选择 | 选填 | 复用 `EmployeePicker`；**非 BOSS 是否允许改负责人需按服务端裁决**，前端只透传，不判断 |

**不做**：企业/门店/团队/角色字段一律不由前端提交（权限先行）。

### 2.3 客户画像编辑（规格）

**Provider**：`customer/customer-portrait/save`（`customerId`）

九个枚举（值来自后端枚举）：

| 字段 | 可选值 |
| --- | --- |
| 决策角色 | Self 本人 / Couple 夫妻 / Parents 父母 / Children 子女 / Unknown 未知 |
| 装修目的 | FirstHome 首套 / Improve 改善 / Wedding 婚房 / SchoolDistrict 学区 / Investment 投资 / Partial 局部 |
| 房屋状况 | Rough 毛坯 / Old 旧房 / Refined 精装 / Pending 待定 |
| 开工窗口 | WithinOneMonth / OneToThreeMonths / ThreeToSixMonths / HalfYearPlus / Undecided |
| 风格偏好 | Modern 现代 / Luxury 轻奢 / NewChinese 新中式 / Cream 奶油 / Wood 原木 / Industrial 工业 / Undecided |
| 环保要求 | Elder 老人 / Infant 婴幼儿 / Pregnant 孕妇 / None |
| 家庭结构 | Single / Couple / ThreePlus / ThreeGenerations / Unknown |
| 付款方式 | Full 全款 / Installment 分期 / Loan 贷款 / Unknown |
| 竞品对比 | None / ComparingOneTwo / ComparingThreePlus / ChosenOther |

另含 **关注点** `concerns[]`（Price 价格 / Duration 工期 / Quality 质量 / Eco 环保 / AfterSales 售后，多选）。

**规则**：画像缺失**不得用默认值补齐**（现状已遵守）；保存后重新读取，不做前端乐观写入。

| 字段 | 新增 | 编辑 | 校验 |

### 2.5 房屋删除门禁（**必须先定规则**）

BR-001 明确「报价、合同和项目必须绑定明确客户与房屋」，SCN-014 也要求「不得伪完成」。因此建议：

| 房屋存在下游对象 | 允许删除 | 提示 |
| --- | --- | --- |
| 量房记录 | ❌ 禁止 | 已有量房事实，删除会丢失设计依据 |
| 设计方案 | ❌ 禁止 | 方案绑定房屋 |
| 报价（含历史版本） | ❌ 禁止 | 报价与合同溯源 |
| 合同 / 项目 | ❌ 禁止 | 履约主链溯源 |
| 以上都没有 | ✅ 允许 | 二次确认后删除 |

实现上更稳的做法（推荐）：**不做物理删除，改为服务端软删/归档**，前端文案为「移除该房屋（可恢复）」。这样避免误删业务事实。

### 2.6 编辑交互形态（建议）

沿用本项目已确立的形态规则：

| 对象 | 形态 | 理由 |
| --- | --- | --- |
| 客户基本信息 | hero 上「编辑」→ 右侧抽屉表单 | 依赖客户上下文，不离开 360 |
| 客户画像 | hero 画像区「编辑」→ 同一抽屉、另一个分组 | 同一对象、字段少 |
| 房屋新增 | 左栏房屋列表底部「+ 新增房屋」→ 抽屉 | 归属明确 |
| 房屋编辑 | 房屋卡上的「编辑」→ 抽屉 | |
| 房屋删除 | 房屋卡上的「删除」→ 二次确认对话框 | 高风险动作要显式确认 |

> 不用路由页：这些是**对象内的就地编辑**，路由页会打断 360 上下文；账户/消息用路由页是因为它们是**独立功能域**，两者不冲突。

## 3. 方向二：Tab 展示丰富（详细规划）

现状：三个 Tab 都是一行摘要。

| Tab | 现状 | 目标 |
| --- | --- | --- |
| 方案 | 名称/状态/版本/面积/空间数/设计项数 | 版本轨 + 空间明细 + 设计项概览 + 状态动作 |
| 报价 | 编号/状态/金额/版本/时间 | 版本轨 + 金额构成 + 客户决策 + 可执行动作 |
| 项目 | 名称/状态/进度/阶段/合同额/经理 | 阶段轨道 + 节点时间 + 风险 + 动作 |

### 3.1 方案 Tab

**列表（按版本倒序）**，每张方案卡展示：

| 分组 | 字段 |
| --- | --- |
| 标识 | 方案名称 / 编号 / 第 N 版 / 状态（草稿·待谈单·已讲解·已选定·已归档） |
| 关键量 | 面积、空间数、设计项数 |
| 归类 | 风格、设计说明摘要 |
| 时间 | 创建时间、更新时间 |
| 关联 | 该方案生成的报价（数量与最新状态） |

**展开后**：空间清单（空间名 + 每空间设计项数 + 面积），设计项按类型汇总（不展示成本价，只展示销售价区间）。

**动作边界**：
- 进入设计工作区（`/designer/design/:id`）
- 标记/推进状态按既有状态机（`build`），不在本页自造
- AI 效果图作为方案内动作（不占菜单）

**空态**：该房屋尚无设计方案 → 引导进入推进工作区创建。

### 3.2 报价 Tab

**版本轨**（同一房屋多版本，DEC-002 口径）：
- `Draft` 草稿：**不进入正式轨道结果**，只作为当前可编辑版本
- `Submitted` 待客户决策
- `Accepted` 客户已接受 / `Rejected` 客户驳回（明确决策结果）
- `Superseded` 已被替代：**只显示历史，不作为当前报价**
- `Converted` 已转项目

**每版本卡展示**：编号 / 第 N 版 / 状态 / 合计金额 / 提交时间 / 客户决策时间与反馈。

**金额构成**（需确认可见字段）：小计、优惠、税率与税额、合计。
> 成本与利润**一律不展示**（成本口径仅企业负责人、店长、财务可见）。

**动作边界**：
- 进入报价工作区（`/designer/quotes/:id`）
- 改版重报：**仅 `Rejected` 可 rebase**（服务端规则），其他状态不显示该动作

**空态**：该房屋尚未生成报价 → 说明报价必须在明确房屋与方案下生成。

### 3.3 项目 Tab

**阶段轨道**：完全读取 `ProjectStage.sort + name + status`，**禁止写死"水电—泥木—油漆—安装"**（DEC-002 §4）。

**项目卡展示**：

| 分组 | 字段 |
| --- | --- |
| 标识 | 项目名称 / 编号 / 状态（待开工·施工中·停工·待验收·已完工·已结算） |
| 进度 | 进度百分比 + 当前阶段名 |
| 金额 | 合同额（金额可见） |
| 排期 | 开工日、计划完工日、是否逾期 |
| 风险 | 停工 / 逾期 / 待验收积压 |
| 角色 | 项目经理；设计师参与范围 |

**动作边界**：查看工地看板、阶段验收（`/designer/projects/:id/acceptance`）。

**空态**：该房屋尚未立项 → 说明项目只能由**已生效合同**创建。

### 3.4 三个 Tab 的共同规则

1. **加载 / 空 / 部分失败三分态**：单个 Tab 失败只影响该 Tab，不整页吞掉。
2. **数量上限**：每 Tab 默认展示最近 N 条（建议 5），超出显示「查看全部」。
3. **口径来源**：状态与金额一律来自服务端，前端不做状态推断。
4. **只读边界**：设计师不展示成本、利润、采购价、供应商历史价。
