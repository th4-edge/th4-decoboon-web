## 1. 信息架构修订（用户 2026-10-10 明确）

增减项菜单不是“新增增减项”的入口，而是**已有变更单**的查看与推进入口。

```text
项目工地
  -> 选择项目
  -> 项目 Hero
  -> 已有增减项变更单列表
  -> 点击变更单进入详情
       -> 查看明细 / 客户线下确认 / 审批 / 生效影响

项目工地对应项目
  -> “发起增减项”
  -> 进入详情页并携带 action=create
  -> 自动打开一张多明细单据
```

- 菜单页：`/workbench/contract-changes`
- 详情页：`/designer/projects/:projectId/changes`
- 发起入口：项目工地对应项目，不在增减项菜单页
- 菜单页不出现“发起增减项”；详情页只有在项目工地明确发起时才打开抽屉

## 2. 菜单页结构

1. 左栏项目工地：当前数据范围内的待开工、施工中、暂停、验收中项目。
2. 中栏项目 Hero：项目、房屋、合同、当前阶段、项目经理、待审批/已生效数量。
3. 项目 Hero 下方：已有增减项变更单列表。
4. 变更单列表字段：状态、单号、原因、类型、金额变化、发起人、创建时间、明细数量。
5. 点击变更单进入详情页，不在这里直接编辑或新增。

## 3. 详情与发起页

详情页保留现有变更单对象工作面：

- 左侧：本项目变更单队列。
- 中间：变更单状态、金额变化、客户线下确认事实、审批事实、明细、证据、办理进度。
- 右侧：当前下一步、可执行动作、业务边界、项目合同上下文。
- 发起抽屉：仅在项目工地发起路径打开，包含变更原因、多行明细、来源、目标报价项目库、客户确认事实和签认证据。

## 4. 三类动作与提交契约

| 用户动作 | 服务端行类型 | 目标 | 关键输入 |
| --- | --- | --- | --- |
| 新增分项 | `Add` | 启用 `CatalogItem` | `targetCatalogItemId` + `targetQuantity` |
| 减项·部分减少 | `Quantity` | 当前有效来源范围 | 来源 + `reduceQuantity` |
| 减项·整项取消 | `Remove` | 当前有效来源范围 | 来源 |
| 替换 | `Replace` | 当前有效来源 + 启用 `CatalogItem` | 来源 + `targetCatalogItemId` + `targetQuantity` |

前端只做来源/目标/数量输入辅助；当前有效剩余、待审批占用、目标金额、成本和差额由服务端计算。

## 5. 权限与状态

| 动作 | 角色 |
| --- | --- |
| 发起/代录 | Designer、Boss、StoreManager、Pm |
| 审批 | Boss、Finance |
| 撤回待审批 | 发起人本人或同团队负责人 |
| 查看变更单 | 按项目数据范围授权角色 |

状态：`待审批 → 已生效 / 已驳回 / 已取消`。历史 `Approved` 仅作为“历史待客户签认”兼容显示。

## 6. 页面状态

- loading：项目、合同、已有变更单分别加载。
- empty：没有项目时显示项目工地为空；项目没有变更单时说明新增入口在项目工地。
- error：项目/合同/变更单失败时显示原因和重试。
- partial：合同成功、变更单失败时保留项目 Hero。
- unauthorized：项目不可见或非发起角色时不出现写入入口。
- stale：来源基线变化或待审批占用冲突时，审批失败并要求撤回重做。
- success：审批通过后回读合同、应收、任务、材料和成本。
