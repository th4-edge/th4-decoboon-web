## 1. 对象与边界

客户意见投诉由业主在小程序提交，员工不能在 Web 代业主创建或关闭。Web 设计师页只处理已有记录：

```text
业主提交意见/投诉
-> 员工查看项目事实、现场说明和承诺解决时间
-> 员工提交处理回复
-> 状态变为已回复
-> 业主确认问题解决后，由业主本人关闭
```

- 菜单页无“提交投诉”“新增意见”。
- 员工页无“关闭投诉”动作。
- 员工只提交处理回复，沿用 App 的员工处理口径。
- 财务角色只读，可查看处理进度，不提交处理回复。

## 2. 页面结构

1. 左栏项目工地：当前数据范围内的项目，显示未关闭数量和全部记录数量。
2. 中栏项目 Hero：项目、房屋、当前阶段、项目经理、设计负责人和意见投诉汇总。
3. Hero 下方：客户意见投诉记录列表。
4. 列表字段：性质、类型、状态、标题、内容摘要、处理人、承诺解决时间和逾期状态。
5. 点击记录：打开处理详情抽屉。

## 3. 详情抽屉

- 客户说明与现场图片。
- 项目、房屋、关联阶段、提交时间、处理人、承诺解决时间。
- 已有处理回复和回复时间。
- 已回复但未关闭时显示“等待业主确认关闭”。
- 已关闭时显示关闭时间与满意度。
- 可处理角色可填写处理回复并提交；提交后状态进入已回复。

## 4. 权限

| 角色 | Web 行为 |
| --- | --- |
| Designer / Pm / Boss / StoreManager | 查看并提交处理回复 |
| Finance | 只读查看 |
| 业主 | 只在小程序提交、确认关闭 |
| 其他角色 | 按服务端数据范围授权 |

服务端 DataScope 与 Provider 是最终边界，前端菜单和按钮只做可见性控制。

## 5. 状态

`待受理 / 处理中 / 已回复 / 已升级 / 已关闭`。

Web 员工动作只将未关闭记录推进到“已回复”；不开放“处理中”“升级”“关闭”按钮。后端支持这些状态，但 App 员工口径与正式业务裁决尚未完整统一，登记 `GAP-WEB-015`。

## 6. 页面状态

- loading：项目和意见投诉分别加载。
- empty：项目为空，或项目没有意见投诉。
- error：项目或意见投诉读取失败时显示重试。
- partial：项目列表成功但意见投诉失败时保留项目工地。
- unauthorized：项目不可见或角色只读时不显示处理表单。
- stale：提交前重新读取记录状态，避免对已关闭/已回复记录重复处理。
- success：提交后回读记录并显示新状态与回复。
