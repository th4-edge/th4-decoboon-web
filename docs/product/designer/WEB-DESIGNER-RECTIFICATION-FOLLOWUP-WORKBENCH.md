# Web 设计师 · 项目交付 · 整改跟进工作台

> 状态：`IMPLEMENTED · 待独立验收`
> 日期：2026-10-10
> 菜单路径：`/workbench/rectification`
> 对象工作区：`/designer/projects/:projectId/acceptance?stageId=...`
> 业务依据：`BR-008`、`SCN-010`、`DEC-007`、`DEC-013`、`DEC-034`

---

## 1. 对象边界

整改不是独立工单。它复用同一阶段、同一张验收单和不限次数轮次。菜单页只跟进“当前处于驳回/整改中”的阶段；整改说明、整改后照片和复验提交进入对应阶段验收工作区完成。

```text
阶段任务完成
-> 提交验收
-> 业主本人驳回并给出问题、整改责任人、截止日期
-> 项目团队整改
-> 菜单页查看整改中阶段和逾期风险
-> 进入阶段验收工作区
-> 提交整改说明 + 整改后照片 + 复验
-> 业主本人再次确认或驳回
```

## 2. 页面结构

1. 左栏：有整改中阶段的项目工地队列。
2. 中栏顶部：项目 Hero。
3. Hero 下方：整改中阶段列表。
4. 每条整改项展示：阶段、轮次、整改类型、整改责任人、问题、截止日期、逾期天数和下一步。
5. 点击整改项：进入对应阶段验收工作区。

菜单页没有“新增整改单”“关闭整改”或“代替业主确认”入口。

## 3. 数据与动作

- 数据 Provider：`project/acceptance/rectify/page`。
- 该 Provider 只返回状态为 `Rejected` 的阶段验收。
- 复验提交仍使用 `project/acceptance/save`。
- 业主确认和驳回只由业主本人执行，员工不能代录。
- 整改循环不改变合同、成本、应收、应付、结算或利润。

## 4. 权限

| 角色 | 行为 |
| --- | --- |
| Designer / Pm / Boss / StoreManager | 查看并进入阶段验收工作区 |
| Finance | 按 `DEC-044` 查看整改事实 |
| 其他项目角色 | 按服务端项目数据范围 |
| 业主 | 在小程序确认或驳回 |

## 5. 页面状态

- loading：整改列表加载中。
- empty：当前数据范围没有整改中阶段。
- error：Provider 失败时显示重试。
- unauthorized：项目不可见时不返回整改项。
- stale：历史轮次或截止日期不可确认时显示阻断，不用 0 伪装。
- success：进入阶段验收工作区后提交复验，回读验收、轮次、阶段和任务。
