## 1. 先承认上一版的问题

上一版虽然删除了前端全量计算、接入了服务端 summary、pipeline、trend 和排名，但本质仍是“把接口已有指标排版成仪表盘”。

它没有充分回答：

1. 这个月我做得比上个月好还是差？
2. 我在团队里处于什么位置，差距来自哪里？
3. 我的客户、量房、设计、报价、签约、交付，哪一段最卡？
4. 我现在先处理什么，处理完之后哪个指标会改善？
5. 这个页面是提醒我工作，还是只让我看数字？
6. 如果没有目标、基期或足够样本，系统是否诚实说明不能判断？

补一个排名，不等于完成分析。

## 2. App 设计师业绩基线

App 当前设计师业绩包含：

- 累计设计签约额；
- 报价规模；
- 最终报价接受率；
- 负责客户、方案报价、报价接受、在施项目；
- 待推进报价、施工任务待推进、逾期任务、现场动态沉淀；
- 最近报价；
- 最近项目及项目进度。

优点：

- 指标直接来自服务端；
- 有“结果 + 待办 + 最近业务对象”三层；
- 设计师可以看到自己负责的业务，不混入其他设计师。

局限：

- 结果指标与当前动作之间缺少因果解释；
- 没有与团队、目标或上月形成可解释比较；
- 没有把“卡在哪一段”讲清楚；
- 最近报价和最近项目只是列表，没有归因分析；
- 对设计师的激励主要来自数字本身，没有下一步改善建议。

Web 应该保留 App 的事实边界，但强化：

- 个人定位；
- 阶段瓶颈；
- 行动优先级；
- 改善结果预测；
- 多周期趋势。

## 3. 设计师真实工作闭环

```text
分配/承接客户
→ 跟进签约前客户
→ 量房
→ 设计需求与方案
→ 方案讲解
→ 报价与客户决策
→ 合同交接
→ 项目排期
→ 主材选材
→ 增减项
→ 阶段验收/整改
→ 交付完成
→ 签约额与交付结果复盘
```

业绩页不能只看最末端“签约额”，否则会把：

- 客户不够；
- 量房在排队；
- 设计方案卡住；
- 报价被驳回；
- 客户迟迟不决策；
- 合同未交接；
- 施工问题拖累交付；

都错误地归因成“本月业绩差”。

## 4. 三类真实设计师场景

### 场景 A：有客户，但签不动

- 线索和客户量正常；
- 量房完成正常；
- 设计任务多，方案完成慢；
- 待谈单或已驳回报价积压；
- 本月报价金额有，但签约金额低。
- 页面应回答：是设计吞吐不足，还是报价转化不足？
- 行动建议：优先推进最久的方案/驳回报价，而不是继续增加客户。

### 场景 B：签约好，但交付风险高

- 本月签约金额排名靠前；
- 在管项目多；
- 逾期任务、增减项、材料或验收问题多。
- 页面应回答：签约结果是否被后续交付质量透支？
- 行动建议：优先处理逾期任务、未选材、待验收和增减项。

### 场景 C：样本少，或项目金额差异大

- 只有 1–2 位设计师；
- 单个大项目导致签约额很高；
- 小项目数量多但总额低。
- 页面应回答：当前排名是否可靠？签约额高是项目大，还是成交效率高？
- 行动建议：显示样本不足和结构性因素，不能简单宣布“第一名优秀”。

## 5. 页面必须回答的六个问题

| 层级 | 用户问题 | 页面输出 |
| --- | --- | --- |
| 1 结果 | 我这个月结果怎么样？ | 本月报价、签约、在途客户、服务端环比 |
| 2 位置 | 我在团队中处于什么位置？ | 排名、团队均值、距第一、较均值 |
| 3 归因 | 差距主要卡在哪？ | 客户→量房→设计→报价→合同的结构与风险 |
| 4 效率 | 我是不是推进得太慢？ | 停留、积压、趋势、负向变化 |
| 5 行动 | 今天先做什么？ | 当前主链 + 2–3 条优先级动作与入口 |
| 6 激励 | 为什么值得继续做？ | 与上月、团队、第一名的可执行差距 |

没有目标或基期时，必须显示“暂无目标 / 暂无基期”，不能编造。

  - 设计师/门店报表分母与去重口径和 `MET-001` 不一致；

### 6.3 需要业务裁决或补实现的指标

| 目标 | 需要的指标 | 当前状态 |
| --- | --- | --- |
| 客户转化效率 | 客户到量房、量房到报价、报价到签约的周期 | 未看到统一正式实现 |
| 报价响应效率 | 驳回后设计师平均修订时长 | 需要服务端时间事实 |
| 客户决策效率 | 报价提交后客户平均决策时长 | 缺统一指标 |
| 设计吞吐 | 方案从创建到讲解/完成周期 | 需要设计域时间事实 |
| 履约质量 | 逾期任务率、验收一次通过率 | Pm 报表有部分，设计师报告未必统一 |
| 目标达成 | 个人/门店月目标与实际差距 | 需要目标对象和口径裁决 |
| 公平排名 | 多指标综合排名或分钟位说明 | 仅单指标排名不足以评价设计师 |

## 7. 排名设计反思

当前已接入“本月签约额排名”，它有两个价值：

- 结果清楚；
- 口径与本月签约金额一致。

但它不能单独代表设计师能力：

- 项目金额受单值大项目影响；
- 新设计师样本少；
- 交接项目和个人新签需要区分；
- 设计师可能承担大量设计工作但不负责签约；
- 企业可能更关心报价接受、设计交付和履约质量。

建议排名分两种：

1. **结果榜**：本月签约金额、签约项目数。
2. **过程榜**：待跟进及时率、量房完成、方案交付、报价响应、合同交接。

在多指标正式裁决前，页面只能把结果榜标为“结果参考”，不能称为综合能力排名。

## 8. “有帮助”的动作建议规则

建议动作必须由服务端给出，不在前端拼规则。

动作优先级建议：

1. 有重大交付风险：逾期任务、停工、验收驳回；
2. 有待客户决策报价超期：推动客户确认；
3. 有驳回报价：优先修订；
4. 有排期最久的待设计任务：先交付方案；
5. 有未选材/待客户确认：推进选材；
6. 当前无风险：保持跟进和趋势复盘。

每条建议必须包含：

- 为什么现在处理；
- 涉及对象和数量；
- 处理后的指标改善；
- 直接进入的合法工作台。

## 10. 结论与下一步

当前已实现的是“结果总览 + 单指标排名”的第一层，不应冒充完整设计师业绩分析。

下一步必须先完成：

1. 冻结正式排名维度与样本规则；
2. 冻结设计师目标对象和月目标口径；
3. 确认可用的周期、风险、履约质量指标；
4. 由服务端输出行动建议和改善影响；
5. 再按最终蓝图重构页面并做真实浏览器验收。

在这些条件未完成前，页面只能显示已实现事实，不得用前端推算补全“能力分析”。
