## 3. 真实场景（≥2）

### 场景 A：单店成长型（10–20 人），设计师同时跟 12 个签约前客户

- 使用人：董夏鹏（设计师）
- 触发事件：周一早上登录，上周有 3 个客户量房完成但未录诉求，2 份报价被驳回，1 份报价确认后 5 天没签合同
- 当前动作：原来要在「客户」「报价」「项目」三个列表之间按状态反复筛选
- 系统下一步：今日主线索直接按阶段聚合——待设计 3、需调整 2、待签约 1（黄色预警），按停留天数倒序，点卡片直接进入处理
- 异常处理：接口失败显示「暂不可确认」+ 重试，不显示空列表

### 场景 B：多店成长型（2–3 店，20–30 人），店长要求设计师批量补报价

- 使用人：谢玲玲（设计师）
- 触发事件：店长集中分配了 8 套同户型房屋，只需要套用同一报价项目库模板微调
- 当前动作：App 上只能一份份编辑，8 份报价要点 8 轮
- 系统下一步：Web 报价工作台提供多选 + 批量套模板 + Excel 式工作区，处理完逐份提交确认
- 异常处理：单份保存失败必须逐份提示失败原因，成功项不回滚，失败项保留可重试

## 4. 对象与状态（冻结口径，来自 BR-005）

| 对象 | 状态集 | 进入设计师工作台的条件 |
| --- | --- | --- |
| 客户 + 房屋 | 量房后 / 设计中 / 方案完成 / 报价中 | `designer_id = 当前员工` 且签约前 |
| 设计状态 | 待设计（无量房）/ 设计中（有诉求无方案）/ 方案完成（有方案） | 以「客户 + 房屋」为一条，多房屋拆分 |
| 报价 | Draft / Submitted / Rejected | `created_by = 当前员工` |
| 报价 | Accepted | 进入签约工作台 |
| 签约 | 待签约（未生成合同/项目）/ 已签约 | Accepted 且客户 `designer_id = 当前员工` |

## 6. 权限矩阵（设计师）

允许（来自后端聚合与角色能力）：查看本人客户/房屋/量房/方案/报价/合同/项目；创建与修改设计、报价、量房；查看报价项目库（`catalog`）；选材；查看本人业绩。

禁止（负向，必须验证）：

| 负向用例 | 期望 |
| --- | --- |
| 查看其他设计师的客户/房屋/报价 | 列表不可见；直开 URL 与接口均拒绝 |
| 报价项目库维护（新增/改价） | 无入口；接口拒绝（设计师无 `catalog:write`） |
| 查看报价项目库标准成本 | 不返回 `costPrice`；页面无成本字段（无 `catalog:cost`） |
| 查看企业财务、成员管理、门店/团队管理 | 无入口；接口拒绝 |
| 跨企业访问 | 拒绝，不泄露对象名称 |
| 未签约客户出现在签约工作台 | 不允许 |

## 7. 可完成状态投影

设计师维度的「今日待办完成」只能由**真实领域对象**推导：

```text
待设计项 = 客户.designer_id = 我 AND 无设计方案 AND 处于签约前
分子 = 其中已有设计诉求的条数
分母 = 待设计总条数
异常态 = 聚合接口失败 → 显示「暂不可确认」，不显示 0/空
```

禁止：前端本地布尔、`done:true`、用空数组伪装完成、把「方案完成」当「已签约」。
