# V2 设计报价功能基线（Web V3 必须完全复用）

> 批次：`DESIGNER-QUOTE-BASELINE-20261006`
> 状态：**功能基线已冻结**（用户 2026-10-06 明确要求）
> 依据：V2 归档实现（`th4-decoboon-web-v1v2-archive`）+ `WEB-设计师报价专项审计.md`
> 用户决策原文：
> 「构建 Web 端的核心推动力是设计师无法在 App 端快捷方便地进行方案报价，
> 所以方案报价的页面设计一定是按照 V2 里的设计报价页面，要完全保障 V2 的设计报价页面功能完全复用我们当前的版本。报价是我们 Web 端装企的核心。」

---

## 0. 复用判定标准

「完全复用」= 下表所有 `必做` 项在 V3 中**可用且可验收**，且不降低任何一项的能力。
任何一项缺失，报价工作台不得判定为完成。

---

## 1. 页面结构基线：桌面三栏

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部：报价工作台标题 + 刷新                                    │
├──────────────┬──────────────────────────────┬────────────────┤
│ 左侧：报价池   │ 中部：报价画布                 │ 右侧：客户上下文 │
│              │                              │                │
│ 搜索          │ 当前客户与房屋身份             │ 客户与联系方式   │
│ 客户/小区/报价号│ 报价状态                      │ 当前房屋/户型/面积│
│ 客户、房屋     │ 报价生命周期轨道               │ 预算            │
│ 报价号、版本   │ 含税金额/小计/税额/版本         │ 当前报价状态     │
│ 报价状态      │ 报价明细（区域/施工分组）       │ 下一步动作       │
│ 报价金额      │ 状态与版本时间线               │ 报价详情/设计依据│
│ 停留天数      │                              │                │
│ 驳回优先排序   │                              │                │
└──────────────┴──────────────────────────────┴────────────────┘
```

**核心设计思想**：报价对象**始终在中央画布**，客户上下文**始终在右侧**，
设计师不需要在方案、报价、合同三个页面之间反复寻找同一个客户。

> V3 可以改进视觉与信息密度，但**不得退化为"列表 + 弹窗"的两栏结构**。

## 2. 功能清单（逐项验收）

### 2.1 报价池（左栏）

| # | 功能 | 优先级 |
| --- | --- | --- |
| Q1 | 按客户 / 小区 / 报价号搜索 | 必做 |
| Q2 | 展示客户、房屋、报价号、版本 | 必做 |
| Q3 | 展示报价状态 | 必做 |
| Q4 | 展示报价金额 | 必做 |
| Q5 | 展示停留天数（驳回 / 待决策 / 草稿 / 已确认分别计龄） | 必做 |
| Q6 | 驳回优先排序（需尽快调整的排最前） | 必做 |
| Q7 | 点击报价准确选中目标对象（按 `quoteId` 匹配，不得回退到列表第一项） | 必做 |

### 2.2 报价画布（中栏）

| # | 功能 | 优先级 |
| --- | --- | --- |
| C1 | 当前客户与房屋身份 | 必做 |
| C2 | 报价状态 | 必做 |
| C3 | 报价生命周期轨道（草稿→提交→接受/驳回→转项目） | 必做 |
| C4 | 金额区：含税金额 / 小计 / 税额 / 版本 | 必做 |
| C5 | 报价明细：按区域 / 施工分组展示 | 必做 |
| C6 | 状态与版本时间线 | 必做 |
| C7 | 草稿状态下在同一画布内直接修改量价 | 必做 |
| C8 | 已提交报价只读；修改必须生成新版本 | 必做 |
| C9 | 已接受报价不可直接修改，须转合同或合同变更 | 必做 |

### 2.3 客户上下文（右栏）

| # | 功能 | 优先级 |
| --- | --- | --- |
| R1 | 客户与联系方式 | 必做 |
| R2 | 当前房屋、户型、面积 | 必做 |
| R3 | 预算 | 必做 |
| R4 | 当前报价状态 | 必做 |
| R5 | **下一步动作**（明确的下一步，不是按钮堆砌） | 必做 |
| R6 | 报价详情与设计依据入口 | 必做 |

### 2.4 版本对比

| # | 功能 | 优先级 |
| --- | --- | --- |
| V1 | 「版本对比」独立 Tab | 必做 |
| V2 | 自动识别同一设计 / 同一客户房屋下的历史版本 | 必做 |
| V3 | 可选对比版本，展示上一版金额、当前版金额、金额变化 | 必做 |
| V4 | 差异筛选：新增 / 删除 / 数量变化 / 单价变化 / 金额变化 | 必做 |
| V5 | 驳回报价标记驳回项，并给出复核建议 | 必做 |
| V6 | 空态：「暂无上一版本」/「两版报价没有分项差异」 | 必做 |
| V7 | **差异只比较两份服务端报价快照，不重新计算正式报价金额** | 必做（口径） |

### 2.5 Excel 式报价工作区

| # | 功能 | 优先级 |
| --- | --- | --- |
| E1 | 表格化编辑报价行：工程量 / 单价 / 金额 | 必做 |
| E2 | 工程量公式（如 `=F2*2`），服务端权威计算 | 必做（待 `GAP-WEB-002` 裁决定位） |
| E3 | 可编辑材料价与人工价 | 必做 |

### 2.6 交互与效率

| # | 功能 | 优先级 |
| --- | --- | --- |
| I1 | Enter：搜索 | 必做 |
| I2 | Ctrl/Cmd + S：保存当前报价草稿 | 必做 |
| I3 | 双击数量或单价：进入行内编辑 | 必做 |
| I4 | 报价行「复制上一行」 | 必做 |
| I5 | 报价表头支持批量改价 | 必做 |
| I6 | 提交客户前检查：成本完整性 / 折扣 / 税金 / 未确认差异 | 必做 |
| I7 | 客户驳回后提供「按反馈调整」而非重新开始 | 必做 |
| I8 | 报价详情底部固定展示金额、状态、当前下一步 | 必做 |

### 2.7 业务规则与口径

| # | 规则 | 优先级 |
| --- | --- | --- |
| B1 | 报价金额由服务端计算，前端不手填、不自算 | 必做 |
| B2 | 报价创建即保存套餐快照，后续修改 BIM 套餐不影响历史报价 | 必做 |
| B3 | 成本不完整时显示「成本未完整」，**禁止伪毛利** | 必做 |
| B4 | 成本可见性按角色：设计师不可见标准成本 | 必做 |
| B5 | 任意金额变更可追溯到报价项、版本、操作人 | 必做 |
| B6 | 页面异常显示「暂不可确认」，**不得显示 0 或空报价** | 必做 |
| B7 | 客户接受后可直接进入签约工作台（设计师侧为合同交接） | 必做 |

## 4. V3 可以改进但不能降级的部分

| 维度 | 允许改进 | 不允许 |
| --- | --- | --- |
| 视觉 | 按 V3 设计系统重做，提升信息密度与层级 | 减少信息项 |
| 布局 | 三档分辨率重新构图（1440/1280/1024） | 退化为列表+弹窗 |
| 性能 | 虚拟滚动、按需加载 | 牺牲功能完整性 |
| 交互 | 增加更顺的键盘流与批量操作 | 去掉 V2 已有的快捷键与批量能力 |

---

## 5. 验收方式

1. 逐条勾选第 2 章功能清单，**任一项「必做」缺失即 FAIL**。
2. 用真实设计师账号 + 真实客户/房屋/方案/报价数据完成一次完整闭环：
   草稿 → 量价编辑 → 提交 → 客户驳回 → 按反馈调整 → 版本对比 → 再次提交 → 客户接受 → 合同交接。
3. 三档分辨率截图 + 至少一条纯键盘路径 + 控制台无未处理错误。
4. 金额口径由服务端核对，页面不得出现 0 或空报价伪装。
