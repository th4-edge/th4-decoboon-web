## 1. 页面为什么存在

设计师每天需要判断：

1. 今天哪些房屋已经具备设计输入，应该先推进？
2. 当前房屋做到哪一步，是否还缺空间、分项、量房依据或设计方案？
3. 哪个方案可以进入待谈单、客户讲解或报价？
4. 完成当前动作后，下一位客户/下一套房屋是谁？

页面不是“方案数据清单”，而是设计师的**设计任务队列 + 单方案工作面**。

### 1.1 本轮实现快照（2026-10-29）

- `/designer/design` 已统一 `PageHeader`，将客户/房屋/方案识别收拢为当前对象条，把客户状态与流失处置降为明确命名的折叠区；设计输入只保留量房结论与操作，删除与对象条重复的房屋摘要；右栏收拢为“判断 → 下一步 → 唯一主行动 → 次要动作”。
- `/designer/design/:designId` 已删除四张同权关注卡和独立下一步卡，改为一条当前判断带；设计分项表成为首屏主工作面；原始结构、量房信息、图纸和参考图收拢到默认折叠的“设计依据与资料”。
- 设计项金额只读取服务端 `calculatedAmount`，自动保存后使用 Provider 返回的新金额与 `priceSource` 更新展示，不在页面重新求和；服务端标记 `unavailable` 时显示“暂不可确认”。
- 未修改后端 Provider、接口字段、权限、状态机、金额公式、表单语义或路由行为。
- 真实渲染与 DOM 证据：`docs/acceptance/runs/20261029-pending-design-ui-upgrade/`。

## 4. 当前问题诊断

### P0 — 结构问题

1. **同一事实重复出现**：方案阶段、报价状态、下一步在页面标题、四张关注卡、下一步卡、右侧动作区重复。
2. **主行动竞争**：顶部操作按钮、下一步卡按钮、方案卡动作和右侧主按钮可能同时出现，用户不知道先做哪个。
3. **对象层级不稳定**：列表页以客户为主，工作区以方案为主；中间不断出现客户、房屋、方案、量房、报价等多层对象。
4. **证据信息抢占工作面**：原始结构表、量房详情和文件区与设计分项同权，用户需要滚动很久才能回到真正要做的设计项。
5. **列表页和详情页职责重叠**：列表页中间已经有方案、量房、诉求和动作，详情页再次展示同一组对象上下文。
6. **前端金额风险**：当前工作区用 `items.reduce(...)` 计算方案金额，和“派生值由服务端生成”的规则存在口径风险；页面优化时应核对并使用服务端权威金额投影。

### P1 — 交互问题

1. 页面解释文字偏多，操作文案与设计原则混在一起。
2. 多个动作以按钮并列出现，缺少按当前状态生成的单一主行动。
3. 列表筛选、选中客户、选中房屋、选中方案与 URL 上下文的恢复规则需要一次完整核对。
4. 设计分项是高频工作面，但页面缺少足够稳定的中区焦点和键盘连续处理路径。
5. 量房、图纸、文件等支持材料应该按需展开，不应与当前任务同权。
6. 页面切换已有一次性 `page-shift`，但页面内部缺少统一的保存、切换空间、自动重算反馈。

### 视觉/AI 味风险

- 卡片和同权信息块过多，容易回到模板化企业后台；
- 中文 eyebrow、泛化页面说明和“阶段/进度/金额/状态”四宫格有模板感；
- 如果继续通过增加更多 KPI、标签或装饰流程来优化，会加重问题；
- 内部编号和搜索编号已由 `BR-060` / `check:identifier-exposure` 禁止，优化不得重新引入。

## 5. 冻结后的页面意图

### 5.1 列表页意图

- 页面类型：行动队列 + 当前对象工作面。
- 第一问题：今天应该先推进哪套房屋的设计？
- 三秒结论：当前列表有多少待设计房屋；选中房屋下一步要做什么。
- 唯一主行动：选中房屋后执行“新建方案 / 打开设计工作区 / 继续推进”。
- L1：待设计数量、当前房屋、当前方案状态、当前下一步；
- L2：量房输入是否足够、方案分项是否齐、下一步是否可报价；
- L3：诉求、跟进、图纸、低频繁资料。

### 5.2 工作区意图

- 页面类型：对象详情工作台。
- 第一问题：当前方案还缺什么，什么时候可以转报价？
- 三秒结论：当前方案是否具备完成条件；主要阻断是什么；下一步只做什么。
- 唯一主行动：由当前方案状态决定的单一动作。
- L1：方案身份 + 状态 + 阻断/下一步；
- L2：空间与设计分项、量房依据、报价状态；
- L3：原始区域表、量房原始记录、文件、历史。

## 6. 目标信息架构

### 6.1 列表页

```text
PageHeader
  当前待设计数量 / 数据更新时间 / 刷新
筛选工具条
  搜索（客户、小区、地址）
  设计状态
  客户 / 房屋
三栏工作台
  左：待设计房屋队列（客户分组，不默认全展开）
  中：当前房屋设计工作面
      对象身份条（客户 · 房屋 · 面积 · 户型 · 状态）
      量房输入摘要（来源、时间、证据数、结论）
      方案轨道（当前方案优先，版本/状态）
      单一主行动
  右：当前判断 / 阻断 / 下一步 / 下一套
      低权重动作：写跟进、查看完整档案
```

列表页不应在中间重复展示完整客户 360；客户低频资料通过“完整档案”进入。

### 6.2 设计工作区

```text
PageHeader
  方案名称 · 客户 · 房屋 · 版本 · 状态
  右侧唯一主行动
结论带
  能否转报价 / 主要阻断 / 当前下一步
主工作面
  左：空间 / 分区导航（含原始结构入口）
  中：设计分项表（当前方案的高频工作面）
  右：当前判断与下一步
      - 方案阻断
      - 报价状态
      - 证据/量房缺口
      - 低权重动作
支持区（折叠）
  量房输入与原始结构
  图纸与参考图
  历史/低频繁资料
```

### 6.3 目标组件

优先复用：

- `PageHeader`：统一页面标题和操作区；
- `BusinessStateTag` / `StatusTag`：状态；
- `MoneyText`：金额；
- `EmptyState` / `WorkbenchState`：七态；
- `DesignItemSheet`：设计分项；
- `DesignSchemeContext`：对象身份上下文，建议减配为一条上下文带，不再作为大卡片；
- `ObjectHeroCard` 或列表页对象身份条；
- `PanelCard`：仅用于单一业务单元，不作为卡片墙。

新增组件需证明现有组件不足；不要复制第二套按钮、标签、表格或抽屉。

## 7. 状态与主行动矩阵

> 下列行动必须以现有 Provider 状态和权限为准；本 brief 只规定视觉主次，不新增状态。

| 当前状态 | 页面重点 | 主行动候选 | 次行动 |
| --- | --- | --- | --- |
| 无方案 / 未量房 | 还缺什么输入 | 新建方案或去待我量房 | 查看客户、量房记录 |
| Draft 设计中 | 继续补齐空间与设计项 | 完成设计，进入待谈单 | 保存、图纸、诉求 |
| Ready 待谈单 | 方案是否具备谈单条件 | 标记已讲解或按现有规则进入报价 | 版本对比、查看报价 |
| Presented 已讲解 | 客户选没选 | 标记客户已选 | 继续报价、查看反馈 |
| Selected 已选中 | 报价是否已生成 | 继续报价 / 生成报价 | 版本对比、查看方案 |
| Archived 已归档 | 只读追溯 | 查看版本/来源 | 返回列表 |

硬规则：

- 一屏最多一个视觉最重的主按钮；
- 顶部和下一步区不得同时出现两个同等级主按钮；
- 主行动不可用时必须说明阻断原因，而不是默默 disabled；
- 完成后回读方案详情并及时更新状态、报价、分项和下一步。

## 8. 交互与动效

- 页面进入：沿用壳层 `page-shift`，页面内部不重复做所有模块入场。
- 设计分项自动保存：显示“保存中 / 已保存并重算 / 保存失败可重试”，不弹循环动画。
- 空间/分项切换：保留当前对象和未保存草稿，切换前有明确提示。
- 主行动：点击后立即反馈 loading；完成后回读并更新下一步，不静默切换客户。
- 失败：保留表单/分项输入，说明影响并提供重试/返回。
- 动效不超过 700ms；`prefers-reduced-motion` 关闭入场和过渡。
- 禁止循环光点、自动呼吸、无业务含义的 2.5D 或面积装饰图。

## 9. 七类状态

| 状态 | 设计要求 |
| --- | --- |
| 正常 | 队列、当前房屋、方案、下一步、更新时间可见 |
| 加载 | 保持列表和主工作面结构；不用空白替代 |
| 真实空 | 区分“无待设计房屋 / 无方案 / 无量房” |
| 筛选空 | 保留筛选条件，提供清除筛选 |
| 失败 | 显示暂不可确认、影响范围、重试/返回 |
| 无权限 | 说明角色边界和后续联系路径，不伪装空数据 |
| 长内容 | 客户/小区/方案名称截断 Tooltip；量房长文折叠；表格横向稳定 |
| 极端值 | 0、null、负数、超大金额、缺单位、缺失状态都有明确表达 |

## 10. 页面级验收门禁

### 结构

- 页面只有一个主行动；
- L1/L2/L3 层级可在 DOM 中识别；
- 同一事实不在两块重复出现；
- 列表页与工作区职责不重叠。

### 数据

- 不展示内部 ID / 系统编号；
- 不展示工作区前端自行计算的正式金额；
- 缺失值显示暂不可确认；
- 状态、报价、数量、金额、版本与 Provider 一致；
- 设计师不因页面新增看到成本/利润。

### 交互

- 筛选 → 选中房屋 → 打开工作区 → 返回恢复筛选/对象；
- 分项编辑失败保留输入；
- 主行动完成后回读；
- 键盘可访问主行动和设计分项；
- 无横向溢出（1440/1280/1024；移动端 390 为补充）。

### 视觉

- 不使用卡片墙、英文 eyebrow、药丸和装饰性流程光效；
- 使用统一 Token、固定字阶、8pt 节奏；
- `check:ai-flavor`、`check:identifier-exposure`、`check:brand-theme`、`check:client-copy` 通过；
- 三档真实截图 + 两轮视觉批判 + `prefers-reduced-motion` 证据。
