## 1. 业务问题

- 当前场景：设计师打开 Web「我的业绩」，需要判断本月结果、团队位置、过程短板和下一步行动。
- 用户/角色：Designer，数据范围 `Self`。
- 现有处理方式：
  - 服务端 `statistic/workbench/designer/report` 已提供 summary、工作卡、pipeline、趋势、分布；
  - 已增量提供“本月签约金额排名、本人名次、团队均值、差额、前 5 名摘要”；
  - 当前排名仅按 `designerMonthSignedAmount`，样本少于 3 人时标记“仅供参考”。
- 希望解决的问题：
  1. 单指标签约额排名是否能作为设计师正式排名？
  2. 设计师业绩是否应有月目标、达成率、目标差额？
  3. 哪些过程效率指标可以正式展示并用于排序？
  4. 行动建议由哪些服务端规则生成，前端只渲染？
  5. 哪些指标存在样本不足、口径冲突或不应展示给设计师的风险？

## 2. 涉及条件

- 主对象：Designer、Customer、Property、Measure、DesignScheme、Quote、ProjectContract、Project、ProjectTask、MaterialSelection、ContractChange、Acceptance。
- 关联对象：Store、Team。
- 当前/目标状态：以现有状态机为准，不新增状态。
- 组织与数据范围：
  - 设计师本人；
  - 排名比较范围待裁决：企业 / 门店 / 团队 / 同岗位。
- 权限：
  - 当前设计师只能看本人和排名的员工摘要；
  - 不开放其他员工客户、报价、项目和财务明细。
- 金额/成本/指标：
  - 可展示本月报价金额、本月签约金额；
  - 不展示成本、毛利、利润；
  - `quoteFinalAcceptanceRate` 当前为 `mismatch`，不得作为正式排名依据。

## 4. 候选方案

### 4.1 排名

1. 保留单指标“本月签约额结果榜”。
2. 增加第二“签约项目数榜”。
3. 建立多指标综合评分：签约额、签约项目数、报价推进、设计交付、合同交接、履约风险。
4. 按“结果榜”和“过程榜”分开，不做综合评分。

### 4.2 目标

1. 暂无目标对象，只显示本月值、上月值和团队比较。
2. 由 BOSS/店长给设计师配置企业月目标。
3. 按岗位通用目标模板自动生成月目标。

### 4.3 效率指标

1. 量房完成周期。
2. 方案创建到方案完成/讲解周期。
3. 报价提交到客户决策周期。
4. 驳回后修订时长。
5. 合同确认到生效周期。
6. 项目逾期任务、验收驳回、变更待确认等履约风险。

### 4.4 行动建议

1. 前端按数值条件拼建议。
2. 服务端返回固定优先级行动列表。
3. 服务端返回行动建议，但不预测改善值。
4. 服务端返回行动建议和预计影响的指标范围。

## 5. 需要业务智能体回答

1. 设计师自看排名应采用什么比较范围：企业、门店、团队还是同岗位？
2. 正式排名应只展示结果榜，还是必须包含过程榜；是否允许建设综合评分？若允许，指标与权重是什么？
3. 设计师月目标是否作为本期业绩页能力？若需要，目标由谁维护、按什么周期和归属生成，未设置时如何展示？
4. 量房、设计、报价响应、客户决策、合同交接的周期指标，哪些已有正式口径，哪些需要新增裁决或实现？
5. 行动建议的优先级和文案是否可由服务端规则输出？请给出一组最低可验收的行动优先级、阻断和完成后回读规则。

## 6. 影响与截止时间

- 影响的模块：
  - Web `/designer/performance`
  - 后端 `statistic/workbench/designer/report`
  - 设计师工作台、量房、设计、报价、合同、项目、材料、变更、验收聚合能力
- 不确认会阻塞什么：
  - 无法确定正式排名和样本规则；
  - 无法确定是否展示月目标与达成率；
  - 无法安全实现周期效率和行动建议；
  - 当前单指标排名不能作为最终综合能力结论。
- 最晚决策时间：最终业绩页视觉和交互冻结前。
