| 使用者 | 7 类员工角色 |

## 2. 设计意图七问

1. 页面类型：B 行动队列。
2. 谁在什么状态下打开：员工登录后或从任意页面返回今日主线。
3. 第一个答案：当前角色有哪些可进入的场景工作台，哪些尚未完成动作裁决。
4. 唯一主行动：从工作台进入对象工作面。
5. 信息优先级：身份/范围 -> 工作台入口 -> 完成后交接。
6. 与 App 差异：Web 以多列、批量进入、深链接和角色场景为主，不展示未经服务端确认的计数。
7. 不做什么：不新增统计口径，不伪造 0，不跨类混排，不把工作台做成模块 CRUD 菜单。

## 3. 构图

```text
┌ 对象身份与数据范围 ─────────────────────────────┐
│ 员工 / 角色 / 企业 / 门店 / 团队 / DataScope      │
├ 今日主线 ───────────────────────────────────────┤
│ 角色工作台卡片：入口场景 + 对象锚点 + 主行动 + 交接 │
├ 状态与治理说明 ─────────────────────────────────┤
│ 未裁决动作显示待业务确认，不显示伪数量/伪完成       │
└────────────────────────────────────────────────┘
```

- 三档布局：1440 三列；1280 两列；1024 两列或单列，卡片不横向溢出。
- 卡片不展示未经服务端返回的待办数量。
- `decisionStatus=pending_business_review` 的入口显示“待业务确认”，主行动不可点击。
- 已批准入口使用可解析的深链接基础路径；带对象占位符的链接先进入工作台/列表，由服务端队列选择对象。

## 4. 对象工作空间骨架

| 区域 | 要求 |
| --- | --- |
| 对象身份条 | 固定显示主对象、子对象、状态、负责人、范围和关键风险 |
| 当前主线 | 显示对象所处主链和已完成/当前/未到达节点 |
| 当前工作面 | 按状态呈现可处理事实；不混入无关模块 |
| 状态动作面板 | 唯一主行动、阻断原因、责任人、前置条件和完成后去向 |
| 草稿区 | 切换、刷新、返回前提供保存/放弃/取消 |
| 回读区 | 动作后按 `reloadScopes` 回读，失败显示部分数据暂不可确认 |
| 安全门 | L3 动作独立确认、幂等、审计和失败恢复 |

## 5. 交互时序

```text
进入工作台
-> 选择卡片
-> 服务端返回对象/状态/允许动作
-> 显示当前事实和唯一主行动
-> 执行动作
-> 提交中/成功/失败/冲突
-> 按 reloadScopes 回读
-> 显示完成后去向和接棒人
-> 用户显式选择下一项
```
