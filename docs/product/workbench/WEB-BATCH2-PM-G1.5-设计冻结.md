## 1. 页面设计意图

| 项 | 冻结结论 |
| --- | --- |
| 页面类型 | B 行动队列 + C 对象工作空间 |
| 使用者 | Pm；Boss 可按岗位视角进入 |
| 打开时第一答案 | 我现在负责哪些项目，哪个项目当前需要推进 |
| 唯一主行动 | 推进当前项目阶段；未冻结动作只显示待业务确认 |
| 信息层级 | L1 项目身份与状态；L2 当前阶段/任务/验收；L3 日报、轮次和证据 |
| App 差异 | Web 侧重多项目并行、阶段比较、任务列表和验收历史；不复刻 App 单项目页面 |

## 2. `/pm` 壳层

一级导航：

1. 今日工作
2. 项目工地
3. 待我选材
4. 待我处理增减项
5. 待我验收/整改

验收和项目工作台为本批主入口；选材、增减项先显示注册入口和待确认状态。

## 3. 项目工作台构图

```text
┌ 项目身份条：项目名/编号/状态/负责人/阶段 ─────────────┐
├ 项目队列             │ 当前项目工作面                 │
│ 待开工/施工中/停工   │ 当前阶段、任务、日报、验收事实   │
│ 待验收/已完工        │ 唯一主行动或待业务确认           │
├ 状态动作面板：原因/责任人/阻断项/完成后去向 ──────────┤
└ 证据区：现场日报、验收轮次、整改记录 ─────────────────┘
```

- 选中项目必须进入 URL：`/pm/projects?projectId=...`。
- 项目列表不使用默认第一条作为业务成功；若仅展示摘要可选择，但刷新后必须恢复 `projectId`。
- 任务/阶段写动作未冻结时，主行动显示“待业务确认”，不得自行拼接按钮。
- 验收提交使用 `project/acceptance/save`，员工不得代业主确认。
- 阶段验收、整改不展示金额区，不改变合同、成本、应收、应付、结算和利润。

## 4. 状态清单

必须覆盖：

- loading / empty / error
- unauthorized / expired
- partial：项目详情、阶段、任务、日报或验收任一读取失败
- stale：项目/阶段/验收版本冲突
- success：动作后显示新状态、接棒人和下游去向

## 5. 三档布局

- 1440：左项目队列 + 右当前项目工作面。
- 1280：左侧收窄，右侧保留任务与验收主区。
- 1024：项目队列折叠为顶部横向选择，主区单列，无横向溢出。

## 7. D3 验收

实现后必须真实浏览器验证：

- `/pm/workbench` 三档截图。
- 项目选择后刷新/返回恢复 `projectId`。
- 阶段、任务、日报、验收事实读取成功或显示部分数据暂不可确认。
- 任务/阶段 pending 动作显示待业务确认。
- 控制台 0 error / 0 warning。
