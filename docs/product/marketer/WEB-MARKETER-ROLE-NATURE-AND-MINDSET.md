## 一、一句话定位

> **业务员是「客户归属范围内的前台执行者」——他的工作单位是「一条跟进」，不是「一个项目」。**
> 他把客户从「有意向」推进到「已安排量房」，然后**放手**：量房结论、设计、报价、合同、项目、钱，都不在他手里。

## 二、与其它角色的差异（思维层）

不是"权限少一点的店长"，而是**工作形态完全不同**的一类角色：

| 维度 | 业务员 Marketer | 对比（设计师 / 店长） |
| --- | --- | --- |
| 生产什么 | **信任与线索推进**（把陌生客户变成可量房的客户） | 设计师生产方案与报价；店长生产经营结论 |
| 时间视角 | **今天这一通电话**（下次跟进时间就是他的工作节拍） | 设计师按方案周期；店长按周/月经营周期 |
| 空间视角 | `Self`：**只看得见自己名下的客户**（跨业务员一律阻断） | 店长 `Store`、负责人 `Company` |
| 核心动作 | 写跟进、安排量房、到店/微信登记、休眠与唤醒、基础信息维护 | 设计师量房/设计/报价/签约；店长分配与干预 |
| 错误代价 | **丢一个客户**（通常不可逆：客户被别家签走） | 设计师错在方案返工；店长错在门店损失 |
| 可逆性 | **跟进动作低可逆**（电话打晚了就是打晚了） | 设计与报价可改版；经营结论可重算 |
| 交互形态 | **移动式、碎片化**：随时随地记一条跟进、拍几张图 | 设计师长驻工作台；店长看板式 |
| 首屏第一答案 | **今天该跟谁 / 谁超期了** | 设计师：待我量房/设计；店长：本店经营结果 |
| 成功判据 | **客户进入 `pendingMeasure`（已安排量房）并最终被签** | 设计师：方案交付与业绩；店长：本店经营结果 |
| 对比对象 | **同期其他业务员**（自己有业绩感） | 店长对比其他门店；负责人对比全局 |

## 三、业务员的五条思维公理（判据 → 约束）

每条都用来回答一个具体设计问题，不是口号。

### 公理 1 · 我的客户就是我的地盘
**判据**：这个入口会不会让业务员看到或操作**别人**的客户？
**约束**：数据范围由**服务端**按登录员工裁决（`DEC-009`）；前端**不得**传 `empId / ownerId` 作为授权依据（`WEB-BATCH6` §2 共同边界）。跨业务员客户一律阻断，页面不得用"我帮你查一下"之类的兜底视图绕过。

### 公理 2 · 我的工作单位是「一条跟进」，不是「一个项目」
**判据**：这个页面/入口的主行动，是不是"写一条跟进"或"安排一次量房"？
**约束**：业务员页面的**唯一主行动**在客户对象上——写跟进或安排量房。设计与项目对业务员是**只读跟踪**，不生成写入口（`BR-006` / `DEC-009`）。把设计/项目工作面复制给业务员＝越界。

### 公理 3 · 我的主链最后一环不在我手里
**判据**：客户量房之后，业务员还能做什么？
**约束**：**量房结论由指定设计师完成**（`measure/save` 角色 = `Designer / Pm / StoreManager / Boss`，**不含 Marketer**；`GAP-WEB-012` 已于 2026-10-10 CLOSED：*业务员仅预约量房，不录结论*）。**指派/改派设计师由店长、团队负责人或企业负责人执行**（`customer/designer-handoff` 角色 = `Boss / StoreManager / TeamLeader`，**不含 Marketer**，真实账号实测 403）。
→ 因此业务员的**闭环终点是「已安排量房 + 可只读跟踪」**，不是"客户转设计"。页面文案不得承诺"我来交接设计师"。

### 公理 4 · 我看不到钱
**判据**：这个区块会不会泄露金额类事实？
**约束**：成本、利润、毛利率、应付、付款、现金流、工资、提成对业务员**一律不生成区块**（`BR-006`）；**不是显示 0、也不是显示 `--`**（显示占位等于承认"这里有个我不知道的数"）。工人档案亦不可见（`BR-007` / `DEC-006`）。

### 公理 5 · 我记的是事实，不是结论
**判据**：这个字段是不是在替别人下结论？
**约束**：业务员只登记**可观察事实**（什么时候联系过、以什么方式、客户说了什么、约了哪天量房）。不得由业务员填写量房结论、设计结论、报价金额或客户成交状态——那些是别人状态机上的节点。

## 四、App 侧业务员能力基线（用于对齐，只读参照）

| 维度 | App 事实 |
| --- | --- |
| Tab | **工作台 / 客户 / 项目 / 我的**（4 个） |
| 首页快捷入口 | **6 个**：我的量房 / 我的客户 / 登记客户 / 签约后流转 / 我的业绩 / 消息通知 |
| 可达页面 | **29 条页面规则**命中业务员能力（详见 `WEB-MARKETER-APP-FUNCTION-MAP.md` §3） |
| 能力数 | **19 项**（含 `view:performance`、`view:commission`、`view:measure-workbench`、`view:feedback`、`act:inviteCustomer`） |
| 主链叙述 | 登记客户 → 跟进 → 预约量房 → 交接设计师；终点「客户转设计」 |
| 强化项 | **批量跟进**、**客户池筛选** |
| 不可见 | 成本与成本变化（整体隐藏，不显示 0 或 `--`） |

**一处口径表述差（不阻塞，已在 §5 登记）**：App 侧叙述把"交接设计师"写在业务员主链里，但 Web 实测 `customer/designer-handoff` 对 Marketer 返回 403（仅 `Boss / StoreManager / TeamLeader`）。**行为以冻结的动作矩阵为准**（业务员不能指派设计师）；需要业务侧澄清的只是"App 里业务员是怎么把客户交出去的"这句叙述。
