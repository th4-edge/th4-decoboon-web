## 一、本批解决了什么

App 侧业务员有 `view:performance`（首页快捷「我的业绩」+ 我的页「我的业绩」），Web **没有 Provider 也没有页面**。M-3 补上：菜单「经营与工具 → 我的业绩」+ 首页卡片（P1）。

页面结构（**结论 → 可执行**，不留"只有数字没有动作"的看板）：

| 区块 | 内容 |
| --- | --- |
| **第一答案** | 本月录入客户（大字）+ 本月量房率 + 本月跟进 + 转化率/平均转化天数 |
| **该我处理** | 到期跟进 / 逾期跟进 → 点击进入「我的客户」（带阶段筛选）；两项都为 0 时显示"当前没有到期或逾期的跟进" |
| 客户阶段结构 | 客户总数 / 跟进中 / 待量房 / 已报价 / 成交 / 已流失 → 点击进入对应客户池 |
| 报价与签约金额 | 报价金额（草稿/已提交数）/ 客户已接受 / 签约金额 |
| 我的节奏 | 录入客户 · 写跟进 · 量房率 × 今日/本周/本月（含环比） |
| 黄金客户分布 | 0-3 天黄金期 / 4-7 天热度期 / 8-15 天降温期 / 15 天+ 风险期（条形图） |
| 同岗排名 | 业务员榜 / 门店榜（我的名次 / 总数 + 榜单表） |
| 最近客户 / 最近项目 | 只读；客户可点进工作面 |

| 项 | 结论 |

## 三、金额边界（本页最容易越界的地方）

| 展示 | 依据 |
| --- | --- |
| 报价金额 / 客户已接受金额 / 签约金额 | **客户侧金额**，App 业务员业绩页同款 |
| **不展示**成本、利润、毛利、应付、付款、现金流 | 业务员无 `view:cost`（`BR-006`）；页面写明"成本与利润对业务员不可见，故不生成区块"——**不是显示 0，是根本不生成区块** |

## 四、结论 → 可执行（本页的关键设计）

业务员看业绩不是为了"看数字"，是为了知道**下一通电话打给谁**。所以：

```
「该我处理」逾期跟进 N  →  点击 → /workbench/my-customers?stage=following
客户阶段结构 任一阶段    →  点击 → /workbench/my-customers?stage=<阶段>
最近客户 某一位          →  点击 → /workbench/my-customers?customerId=<id>
```

**参数必须在目标页真的被消费**：「我的客户」页本轮补了 `?stage=` 消费（切换阶段筛选并重新加载），`?customerId=` 在 M-2 已实现消费。两处都不是死参数（`EXP-013`）。

## 六、顺带澄清的一处**能力与实现的差异**（重要）

`view:commission`（提成）在 App 能力矩阵里**声明**了，但全仓 grep 后确认：**App 没有任何页面或入口使用它**（`payroll` 域的提成页由 `view:payroll` 等管理能力门禁，不是业务员的自助提成）。

→ 因此 `WEB-MARKETER-APP-FUNCTION-MAP.md` 里把"提成"列为业务员功能是**不准确**的，已修正为「**能力已声明、App 未落地入口**」，归入"待业务确认"而不是"待实现"。

> 教训：**能力矩阵声明 ≠ 已实现功能**。判据要看"有没有页面/入口在用它"，否则会凭空造出一个没有业务依据的页面。
