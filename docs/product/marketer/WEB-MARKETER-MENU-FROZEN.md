## 二、设计原则

1. **以 App 的「入口级」结构为准**：App 的 Tab 与首页快捷 = 必须有的 Web 入口；App 的上下文子页 = 由父页面的抽屉/详情承接，**不各占一个菜单项**（`DEC-034`：对象不进菜单）。
2. **未建页面不挂入口**（不留死链，`EXP-013`）；冻结稿写**目标态**，静态源只写**已建态**，二者差异由本稿「实施状态」表交代。
3. **只读就是只读**：业务员拿到的"别人域"页面一律只读，不得带入写入口。
4. **文案 = App 文案**：优先沿用 App 的入口命名（我的量房 / 签约后流转 / 我的业绩），保证跨端同词。
5. **动作不占菜单**：登记客户、微信登记、到店登记等在页面内以主行动/行内动作呈现，不做入口级菜单项。

[今日]        业务工作台        today.mainline       → /workbench                     ✅ 已建
[客户经营]    我的量房          customer.measure     → /workbench/measure             ✅ 已建

- **一级 4 组**（≤7 ✅）；组名用场景语言；
- **不占菜单项**：消息通知（顶栏已有）、我的工资条（首页卡片，`GAP-WEB-023` 待拍是否全角色进菜单）、登记客户/微信登记/到店登记（页内动作）、只读项目子页（由「签约后流转」页内承接）。
