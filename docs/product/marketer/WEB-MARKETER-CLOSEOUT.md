## 一、修了两个真问题（都是"不报错但不对"）

### 1.1 M-4 的 `?projectId=` 深链接被静默吞掉（**我自己写的 bug**）

```js
// 错：load() 未 await，projects 还是空数组时 find 必然落空
onMounted(() => {
  void load()
  const target = projects.value.find((item) => item.id === String(route.query.projectId ?? ''))
  if (target) await openDetail(target)
})
```

→ 改成 **先 `await load()` 再消费**，并加 `watch(route.query.projectId)`；已用 `activeProject` 去重避免重复打开。

> 这是我在 M-2/M-3/M-4 一直强调的「深链接必须真的被消费」——**结果自己在 M-4 里犯了一次**。
> 教训：深链接消费是**异步依赖**（数据在前、参数在后），"并行写两行"看起来对，实际必然失败，且**不报错**。

### 1.2 「我的业绩 → 该我处理」跳过去后，用户看不出谁到期了

「到期跟进 / 逾期跟进」点击后进「我的客户」并筛到「跟进中」——但**客户页原来没有"下次跟进"列**，用户到了池子里还是要逐个点开看。

→ 客户页新增 **「下次跟进」列**（`Customer.nextFollowAt`），**已到期的行标红并显示「· 已到期」**；业绩页 CTA 旁加一句诚实说明：*「进入跟进中客户池；到期与逾期请按列表的『下次跟进』列核对（服务端暂不支持按到期筛选）」*。

> 处理方式说明：**没有假装能做筛选**。服务端 `customer/customer/page` 只支持 `keyword + status`，做客户端筛选只能过滤已加载的一页（误导），所以选择"把列显示出来 + 明确说明限制"。

## 二、4 项"待核"的结论（不再挂账）

先说判据：**App 的「入口级结构」里有没有它**。
App 业务员的两类入口是 **4 个 Tab**（工作台/客户/项目/我的）与 **6 个首页快捷**（我的量房/我的客户/登记客户/签约后流转/我的业绩/消息通知）。
下面 4 项**都不在其中**——它们全部位于 App「我的」页的**「经营资料」区**或**「业务」区**：

| # | 能力 | App 实际位置 | **结论** | 承接 |
| --- | --- | --- | --- | --- |
| 1 | 报价项目库（`view:catalog`，只读） | 我的 → 经营资料 | **不进业务员工作台菜单** | 归 **J-1「经营资料只读」** |
| 2 | 套餐模板（`view:package-template`） | 我的 → 经营资料 | 同 #1 | **J-1** |
| 3 | 付款计划模板（`view:payment-plan-template`） | 我的 → 经营资料 | 同 #1 | **J-1** |
| 4 | 施工计划模板（`view:construction-plan-template`） | 我的 → 经营资料 | 同 #1 | **J-1** |
| 5 | 内容任务 / 我的内容 | 我的 → 业务 | **本批不做**：Web **完全没有内容获客域**（无 Provider 无页面），属跨角色能力 | **J-2「内容获客」**（跨角色立项） |
| 6 | 提成（`view:commission`） | **App 无入口**（全仓确认） | **业务澄清项**，不是待实现项 | 回业务侧 |

**J-1 的建议做法（供后续批次）**：这 4 项是**全部内勤角色共用的"查阅企业标准"**，App 放在「我的」区而非主导航——
因此正确做法是**一次做「经营资料（只读）」共享区**（4 个只读页 + 4 个 Provider），按角色授予只读可见性，
**而不是把它们塞进业务员（或任何单角色）的工作台菜单**。塞进菜单会同时违反两件事：与 App 入口级结构不一致、把一个"查阅"能力伪装成"日常推进"。

**J-2**：内容获客是**独立业务域**（内容任务/我的内容/内容线索），不属于任何单角色批次。

### 业务员菜单因此**保持 6 项 / 4 组不变**（不新增）

| 组 | 项 |
| --- | --- |
| 今日 | 业务工作台 |
| 客户经营 | 我的客户 · 我的量房 |
| 项目履约 | 签约后流转 · 客户意见投诉（只读） |
| 经营与工具 | 我的业绩 |
