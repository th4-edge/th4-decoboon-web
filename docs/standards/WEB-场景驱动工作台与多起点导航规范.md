# Web 场景驱动工作台与多起点导航规范

> 状态：生效并强制执行（2026-10-07）
> 上位依据：`DEC-034`、`BR-030`、`DEC-033`、`BR-029`、`DEC-002`
> 业务事实源：全局 `zhuangdeqing-business`；本文不新增、不修改业务对象、状态、动作、权限、金额、成本或利润口径。
> 适用范围：Web 一级导航、角色首页、今日主线、工作台、菜单、深链接、上游交接和完成后交接。

---

## 1. 要解决的问题

沉浸式对象工作空间解决“用户获得一个起点后，如何不中断地走到终点”。
本规范解决另一个问题：

> 用户登录系统时，起点不是唯一的。设计师可能从量房、设计、报价或合同进入；项目经理可能从项目、选材、增减项或验收进入；财务可能从应收、应付、收付款或台账进入。

因此：

```text
沉浸式操作 = 进入后怎么走完
本规范 = 用户从哪里进入，以及完成后交给谁
```

两者共同构成完整 Web 操作模型：

```text
多起点入场
-> 同一对象锚点
-> 状态驱动唯一主行动
-> 沉浸式连续推进
-> 完成后明确交接
```

## 2. 工作台正式定义

工作台不是业务对象，也不是功能模块页面。

```text
工作台 =
  入站队列
  + 当前对象工作面
  + 唯一主行动
  + 完成后去向/接棒人
```

| 概念 | 定义 |
| --- | --- |
| 入站队列 | 哪些对象因角色、状态、时间、风险和触发事件进入我的工作台 |
| 对象工作面 | 当前对象的业务事实、状态、责任人、阻断项和操作区域 |
| 唯一主行动 | 当前状态下最该做的动作，其余动作降级 |
| 完成后去向 | 完成后进入什么状态、交给谁、出现在谁的哪个工作台 |
| 起点 | 角色 × 触发事件 × 对象状态 × 当前责任 |
| 多起点导航 | 今日主线、角色工作台、通知、搜索、上游交接、深链接等多入口进入同一对象主线 |
| 同锚点 | 客户 + `activeProperty`、项目 + 阶段、财务 + 单据等显式对象上下文 |
| 同状态源 | 所有入口读取同一套服务端状态和允许动作 |
| 同工作面 | 进入后复用同一对象工作空间，只切换当前工作面 |

## 3. 工作台准入契约

每个工作台必须在 `docs/standards/workbench-navigation.json` 登记，至少包含：

```text
key
label
domain
group
kind
roles
entryScenario
inboundStates
objectAnchor
mainline
currentWorkSurface
mainAction
actionPolicyKeys
handoff
handoffTo
priority
deepLink
emptyState
exceptionState
contextRecovery
unsavedChangesGuard
reloadScopes
decisionStatus
businessRefs
```

要求：

1. `key` 稳定、唯一，不得用页面标题代替。
2. `label` 使用使用者语言，如“待我量房”“待我报价”“待我收款”，禁止“量房管理”“报价管理”等模块 CRUD 命名。
3. `inboundStates` 必须指向已登记业务对象和状态；未登记规则标记 `pending_business_review`。
4. `objectAnchor` 必须显式，多房屋、多项目、多单据时必须选择当前子对象。
5. `mainAction` 必须唯一且可解释；其余动作不得同权。
6. `handoff` 必须写清完成后进入什么状态、交给谁、出现在哪个下游工作台。
7. `emptyState` 必须说明为什么空、下一步可以做什么。
8. `exceptionState` 必须覆盖规则未命中、数据缺失、权限不足、部分读取失败。
9. `deepLink` 必须可刷新、可返回、可携带对象锚点。
10. `businessRefs` 必须回指 `DEC-034 / BR-030` 及相关 `SCN / BR / MET`。

## 4. 菜单架构

一级导航遵守 `DEC-002`，控制在 7 项以内：

```text
今日主线
客户经营
项目工地
商务财务
经营分析
更多
```

第二层是角色业务域 / 场景工作台，例如：

```text
客户经营
  ├── 客户跟进
  └── 设计报价
        ├── 待我量房
        ├── 待我设计
        ├── 待我报价
        └── 合同交接

项目工地
  ├── 项目推进
  ├── 待我选材
  ├── 待我处理增减项
  └── 待我验收/整改

商务财务
  ├── 待我收款
  ├── 待我付款
  └── 资金台账与凭证

经营分析
  └── 待我处置风险
```

规则：

1. 默认落地页为“今日主线 / 需要我处理”。
2. 高频工作台置顶或固定；低频工作台通过搜索、通知、深链接和上游交接进入。
3. 同一功能不得在多个菜单重复出现。
4. 菜单徽标只统计需要我处理的数量或风险，不显示与我无关的总量。
5. 菜单可见性不等于权限；服务端最终校验数据范围和允许动作。
6. 禁止模块菜单、实体菜单、全量台账菜单和空白 CRUD 入口。

## 5. 角色工作台地图

| 角色 | 主工作台 | 默认入口 | 强制边界 |
| --- | --- | --- | --- |
| Marketer | 客户跟进、邀约量房 | 今日主线 | 不越权修改设计、报价、合同、财务 |
| Designer | 量房、设计、报价、合同交接 | 今日主线 | 多房屋显式选择；不展示成本/利润 |
| Pm | 项目、选材、增减项、验收/整改 | 今日主线 | 不改合同金额、不回退正式状态；成本按权限 |
| Finance | 应收、应付、收付款、台账/凭证 | 今日主线 | 高风险动作保留确认、幂等和审计 |
| Boss / StoreManager / TeamLeader | 风险队列、客户经营、项目工地、商务财务、经营分析 | 今日主线 | 按组织层级和数据范围；不直接改写状态机 |
| 一人装企 BOSS | 全部内部岗位工作台 | 今日主线可切换岗位视角 | 逐步留痕；不伪造操作人；不能冒充外部业主/客户确认 |

## 6. 多入口一致性

```text
多入口：今日主线、工作台、通知、搜索、上游交接、深链接。
同锚点：客户 + activeProperty、项目 + 阶段、财务 + 单据等显式上下文。
同状态源：所有入口读取同一套服务端状态和允许动作。
同工作面：进入后复用同一对象工作空间，只切换当前工作面。
```

必须满足：

1. 从任何工作台点击一条业务，直接进入对象工作面，不得再进入泛列表搜索。
2. 从不同入口进入同一对象，状态、金额、权限、动作和时间线必须一致。
3. 上游未完成或未生效时，下游工作台不得提前显示为可执行。
4. 切换对象、打开全屏或安全门前有未保存草稿时，必须提供保存后切换、放弃并切换、取消三条路径。
5. 刷新、浏览器前进后退、深链接必须恢复对象 + 子对象 + 工作面 + 必要筛选。

## 7. 完成后交接

| 工作台 | 完成条件 | 完成后去向 |
| --- | --- | --- |
| 量房工作台 | 量房事实已登记且满足既有规则 | 设计工作台出现该客户 + 房屋 |
| 设计工作台 | 方案达到既有可报价条件 | 报价工作台出现可报价对象 |
| 报价工作台 | 报价达到既有提交/接受/驳回/替代结果 | 合同工作台或报价改版队列 |
| 合同工作台 | 合同达到既有生效条件 | 项目工作台按合同生效结果创建/出现项目 |
| 项目工作台 | 当前阶段/任务完成 | 选材、增减项、验收、财务等对应工作面 |
| 选材工作台 | 选材确认或换材完成 | 采购、成本、应付相关投影刷新 |
| 增减项工作台 | 变更确认/重算完成 | 任务、材料、应收、成本相关投影刷新 |
| 验收/整改工作台 | 验收确认或复验通过 | 项目继续或结算路径 |
| 收付款/对账工作台 | 收付款/核销/对账完成 | 台账、凭证、项目回款/成本投影刷新 |

完成后必须显示：去向、接棒人、下一状态、下游工作台和需要回读的关联对象。
任一回读失败显示“部分数据暂不可确认”，不得用旧值或空数组伪装完成。

## 8. 一人装企规则

1. BOSS 可以使用全部内部岗位工作台，也可以切换岗位视角或查看合并今日主线。
2. 同一 BOSS 连续执行多个岗位节点时，状态机逐步推进，每个动作分别留痕。
3. 不得把“同一人操作”写成不可追溯的单一动作。
4. 不得伪造不同操作人；审计记录实际操作用户和承担的岗位能力。
5. BOSS 仍不能冒充外部业主/客户确认。

## 9. 反模式（一票否决）

1. 按数据库实体或功能模块做菜单。
2. 工作台进入后只是全量台账或空白 CRUD 列表。
3. 有页面、无入站队列；有列表、无唯一主行动；有动作、无完成后交接。
4. 用户从工作台进入后还要重新搜索同一对象。
5. 从不同入口进入同一对象时状态、金额或动作不一致。
6. 上游未完成，下游工作台提前显示可执行。
7. 徽标统计与队列实际数量、权限范围不一致。
8. 菜单不可见被当作服务端权限校验。
9. 一人装企合并留痕或伪造操作人。
10. 工作台绕过高风险动作的确认、幂等和审计。

## 10. 自动门禁

机器注册表：

```text
docs/standards/workbench-navigation.json
```

必须运行：

```bash
npm run check:workbenches
npm run check:workspaces
```

检查内容：

- 工作台注册字段完整；
- 角色、场景、领域、分组合法；
- `inboundStates` 引用有效对象和状态；
- `actionPolicyKeys` 引用有效动作；
- `handoffTo` 引用有效工作台；
- 角色工作台覆盖完整；
- 菜单标签不得为模块 CRUD 命名；
- 对象锚点、主行动、完成后交接、上下文恢复和 `reloadScopes` 完整；
- 多入口同锚点、同状态源和同工作面契约存在。

- [ ] 入站队列、对象锚点、唯一主行动、完成后交接完整；

- [ ] `check:workbenches`、`check:workspaces` 通过；
