# Web 客户提醒日期与天数展示规范

> 状态：生效并强制执行（2026-10-09）
> 适用范围：客户经营、待我跟进、客户 360、房屋、跟进记录、量房预约及所有需要面向用户提示“什么时候联系/处理”的 Web 页面。
> 上位依据：`BR-005`、`BR-036`、`DEC-034`、`DEC-042`

---

## 1. 目的

客户经营中的日期字段不是审计时间，而是行动提醒。用户首先需要知道：

```text
今天做 / 明天做 / 几天后做 / 已经晚了几天 / 还没安排
```

因此，客户提醒日期不得在页面上直接展示一长串绝对时间，也不得让用户自己做日期差计算。

---

## 2. 统一表达

| 场景 | 展示文案 |
| --- | --- |
| 无日期 | 未安排 / 未设置下次联系 |
| 今天到期 | 今天到期 / 今天 |
| 明天到期 | 明天联系 / 明天 |
| 未来 N 天 | N 天后联系 / N 天后 |
| 已逾期 N 天 | 已逾期 N 天 / 已过去 N 天 |
| 无效日期 | 时间待确认 |

未来天数按自然日计算，不按小时四舍五入；逾期按自然日计算。

## 3. 使用边界

- “下次跟进 / 下次联系 / 下次量房 / 到期”等行动提示字段，统一使用相对天数。
- 审计时间、创建时间、提交时间、成交时间等事实记录继续使用标准日期时间，不伪装成相对天数。
- 同一页面同一字段只能有一种表达；列表、Hero、提醒条和抽屉中的下次联系文案必须一致。
- 颜色只表达风险：逾期用危险色，今天/明天用提醒色，未来几天用品牌信息色；颜色不能代替文字。
- 相对天数必须由统一格式化函数生成，禁止各页面自行写 `slice(5, 10)`、`before` 或字符串拼接。

## 4. 客户经营页面要求

- Hero 的“下次联系”显示 `今天 / 明天 / N 天后 / 已逾期 N 天`。
- 左侧队列显示相同相对天数，不用绝对日期抢占空间。
- 右侧主行动区必须显示行动提醒：
  - 已逾期：`已逾期 N 天` + `建议优先联系，避免客户流失`
  - 今天：`今天到期` + `按约定完成本次联系`
  - 未来：`N 天后联系` + 提前准备沟通内容
  - 未安排：`未安排下次联系` + 建议本次沟通后约定时间
- 保存跟随后，Hero、队列、提醒条和最近沟通记录必须同步回读更新。

## 5. 代码约定

统一使用 `src/core/format.ts`：

```ts
formatRelativeDay(value)
formatFollowDue(value)
```

页面不得直接使用 `formatDateTime(nextFollowAt)` 作为客户提醒主文案；完整日期时间只允许在历史记录、查看详情或审计上下文中出现。

## 6. 验收

- 无日期、今天、明天、未来 3 天、逾期 1 天、逾期 30 天均有正确中文文案。
- 保存下一次跟进时间后，Hero、队列、提醒条同步变化。
- 1440、1280、1024 三档无日期溢出。
- 页面不出现后端英文日期格式、ISO 时间串作为主提醒。
