# 装得清 Web 端开发规范

> 状态：**待确认**（确认后为本工程唯一 Web 开发总纲）
> 版本：v1 草案 · 2026-10-06
> 上位依据：`docs/standards/WEB-建设核心思路.md`（四条公理）
> 业务事实源：全局 `zhuangdeqing-business`；本文不新增、不修改任何业务口径
> 提炼来源：用户四条原则 + V2 归档规范（App 动作对齐、页面开发总纲、对齐矩阵）+ 当前工程实践

---

## 0. 文档地位与冲突处理

1. 本规范是 Web 页面"能不能做、怎么做、做完算不算完成"的唯一判定依据。
2. 与任何其他文档冲突时，以本文为准；同时修订被冲突文档。
3. 与业务口径冲突时，以 `zhuangdeqing-business` 为准，并建立 `GAP-*`，不得自行选择更省事的版本。
4. 四条公理（App 为准 / 不新开 API / 不复刻 App / 禁止堆砌与 CRUD）与本文同级，不可协商。

## 1. 页面生成与准入（先于一切）

### 1.1 生成公式

```text
页面 = 角色 × 场景 × 业务对象 × 对象状态 × 唯一主行动
```

### 1.2 准入三问（答不出就不做）

1. 哪个角色、在什么状态下打开？
2. 他打开后要拿到的第一个答案是什么？
3. 唯一主行动是什么，做完进入什么状态、交给谁？

### 1.3 场景要求

任何新页面至少写清 **2 个真实中小装企场景**，每个场景必须包含：

```text
使用人 | 触发事件 | 前置条件 | 当前动作 | 系统下一步 | 异常处理
```

全链批次至少覆盖 3 个租户画像（单店成长型 / 多店成长型 / 小团队兼任型）。
人物、房屋、金额、账号一律使用合成数据。

### 1.4 进度衡量

- 以**角色闭环数 + 效率提升 + 验收证据**衡量进度。
- **不以页面数、菜单数、接口数衡量进度。**
- 每个入口必须挂在某角色的主链闭环上；挂不上就不建。

## 2. 角色与壳层

### 2.1 角色（固定 7 类，禁止新增）

`Boss` / `StoreManager` / `TeamLeader` / `Marketer` / `Designer` / `Pm` / `Finance`

### 2.2 数据范围默认矩阵

```text
Boss = Company
StoreManager = Store
TeamLeader = Team
其他员工 = Self（外加项目参与关系）
```

### 2.3 壳层

| 壳层 | 面向 | 一级导航原则 |
| --- | --- | --- |
| 经营管控层 | Boss | 结论 → 风险 → 下钻；不承载普通员工批量录入 |
| 岗位执行层 | 其他角色 | 按工作阶段聚合待办；菜单按角色能力过滤 |
| 共享对象层 | 全角色 | 同一对象只允许投影差异（可见字段、动作集合），不允许口径差异 |

### 2.4 角色与入口

- 入口（菜单、按钮、深链、动作）由**角色 + 权限 + 数据范围**共同决定。
- 不允许"顺手都放上去"。
- 一级导航建议 ≤7 项；超过说明没有按阶段聚合。

---

## 3. 页面原型（只允许六类）

| 原型 | 用途 | 唯一主行动 |
| --- | --- | --- |
| A 决策页 | 老板判断经营与风险 | 下钻到风险/事实 |
| B 行动队列 | 岗位处理今日待办 | 处理当前事项 |
| C 对象工作空间 | 单个业务对象全貌与推进 | 推进到下一状态 |
| D 专业列表 | 批量查询、筛选、对账、导出 | 查询 / 批量操作 |
| E 表单抽屉 | 新增 / 编辑 / 确认 | 提交 |
| F 单据文档 | 合同、报价单、报表的正式输出 | 生成 / 导出 / 打印 |

**禁止**：一个页面同时承担多种原型；禁止页面自造第七类原型。

---

## 4. 首屏三问与信息层级

### 4.1 首屏三问（必须同时回答）

1. **我是谁**：当前员工 + 角色 + 数据范围。
2. **当前有什么待处理**：我的待办 / 风险 / 逾期 / 等待他人 / 待决策。
   无待处理时**必须明确说明**，不得留空白。
3. **下一步该做什么**：唯一主行动 + 为什么现在做 + 谁负责 + 完成条件 + 做完进入什么状态。

### 4.2 信息层级（一屏最多三层）

```text
第一层 结论：状态 / 关键金额或数量 / 风险 / 完成度（带口径与 asOf）
第二层 行动：下一步 / 责任人 / 阻断项 / 交接对象
第三层 证据：明细 / 留痕 / 附件 / 历史
```

### 4.3 页面身份

页面身份只允许一处承载；禁止壳层标题 + 页面标题 + 身份条三重表达。

## 5. 交互设计准则（Web 相对 App 的提升要求）

### 5.1 必须做（Web 存在的理由）

| 能力 | 要求 |
| --- | --- |
| 批量 | 同质业务可多选批量处理，不要求逐条重复操作 |
| 对账 | 多列并排、可比对、可标记差异 |
| 并行 | 切换对象不丢失列表筛选、分页、滚动位置 |
| 键盘 | 至少主链的常用动作可纯键盘完成 |
| 密度 | 一屏承载更多有效事实，而不是更多卡片 |
| 比较 | 支持多对象横向对比（多报价、多项目、多客户） |
| 输出 | 单据 / 报表可导出、可打印 |
| 经营 | 结论先行、风险优先、可逐层下钻 |

### 5.2 操作步数

- 完成页面主任务 **不超过 3 次操作**。
- 每一步必须有确定反馈；禁止"点了不知道会发生什么"和"点了没反应"。

### 5.3 交互时序

```text
用户动作 → 即时反馈 → 处理中 → 结果反馈 → 失败恢复
```

### 5.4 禁止

- 禁止把 App 页面等比放大。
- 禁止一个页面多个主行动。
- 禁止用装饰（渐变、阴影、图标堆砌）掩盖信息层级问题。

## 6. 状态与异常（必须全覆盖）

每个数据页面必须实现以下状态（App 与 Web 取并集）：

```text
正常 / 加载中 / 真实为空 / 请求失败 / 无权限 / 会话过期 /
提交中 / 提交成功 / 提交失败 / 业务状态冲突 / 长内容与极端值
```

规则：

- **真实为空**与**请求失败**必须区分：前者给下一步，后者给重试。
- 接口失败一律表达为「暂不可确认」，**禁止用 0 或空数组伪装成功**。
- 业务状态冲突（如对象已被他人推进）必须给出重新读取的恢复路径。
- 提交必须幂等防重。

---

## 7. 动作与接口对齐（App 为准）

### 7.1 动作对齐

- App 在某个状态下能做的动作，Web 同角色同状态必须**可达**，且无需记忆隐藏路径。
- App 是"队列 → 一键动作"的，Web 也必须给队列，不能让用户在详情里翻找按钮。
- 涉及两个业务事实的动作（如签约 → 生效立项）必须**分两步显式确认**，不得静默推进。

### 7.2 禁止新开 API

- Web 只能消费 App 已在使用的既有 Provider 路由。
- 每个页面用到的 Provider 路由，必须能指出 App 中的对应调用点。
- 需要新数据时，回到 App 与后端决策，**不在 Web 侧开小口**。
- 禁止 Web 专属路由、Web 专属字段、Web 专属状态。

### 7.3 命名一致

禁止用同一个名字表示不同能力（反例：把设计师的"合同交接"页叫"签约工作台"）。

---

## 8. 权限与数据范围

- 企业、门店、团队、角色、数据范围一律从登录会话加载；
  **禁止信任前端传入的 `companyId / empId / ownerId`**。
- 三层缺一不算通过：
  1. 菜单/入口不可见
  2. 路由守卫拒绝（含直开 URL、改参数、刷新）
  3. 接口拒绝
- 前端隐藏不等于授权，服务端必须强制校验。
- 负向用例必须覆盖：跨企业、跨门店/团队、同角色他人数据、直连接口。

---

## 9. 金额、成本与利润

- 金额、成本、利润、计数一律由服务端返回，**页面不得自行计算业务金额**。
- 成本价、成本明细、利润、毛利率仅企业负责人、店长、财务可见；
  其他角色**不生成该区块**。
- 应计成本缺失时 `costComplete=false`，利润与毛利率返回 `null`，
  页面显示「成本未完整」，**禁止以 0 成本展示伪利润**。
- 经营数字必须带口径、周期与数据截止时间 `asOf`。
- 同一业务事实在 App 与 Web 必须一致；不一致建立 `DEF-*`，禁止单端改文案掩盖。

---

## 10. 工程实现约定

- **无 DTO**：直接消费领域实体，对象关联保持对象形态（`Employee` 而非 `empId`）。
- **请求层唯一**：所有请求走统一请求层；错误统一为可识别的业务错误（含 code）。
- **状态机在后端**：页面只提交对象或调用领域能力，然后重新拉取；禁止前端本地状态机。
- **路由集中管理**：禁止魔法路径字符串。
- **禁止静默兜底**：不得用 `||`、`??`、`0`、空数组掩盖后端缺失字段。
- **类型严格**：禁止 `any`；外部数据用 `unknown` + 收窄。
- **按需引入**：禁止整库导入 UI / 图标 / 图表库。
- **App 兼容优先**：共享后端只做向后兼容的加法，不得改变 App 已依赖的路由、参数、字段语义、状态机与金额口径。

---

## 11. 设计系统

- **唯一视觉真源**：`src/styles/tokens.scss`；页面禁止裸色值、裸字号、裸圆角。
- **字号**：正文 ≥13px，辅助信息 ≥12px；更小字号仅限角标等非阅读文本。
- **断点**：只允许 1440 / 1280 / 1024 / 768。
- **状态表达**：文字 + 颜色 + 位置（必要时图标），禁止只靠颜色。
- **可访问性**：禁止 `outline: none`；键盘可达；焦点可见；对比度达 AA。
- **组件**：先复用既有组件；新增组件必须说明现有组件为何不满足。

## 12. 反模式清单（一票否决）

出现以下任一条，页面**不得交付**：

| # | 反模式 | 说明 |
| --- | --- | --- |
| 1 | 从后端模型生成 CRUD 页面 | 因为是 `Customer` 实体就做"客户管理"增删改查 |
| 2 | 功能菜单堆砌 | 左侧罗列功能名，每个功能一张表 |
| 3 | 一级导航超载 | 一级导航 >7 项且未按角色/阶段聚合 |
| 4 | 复刻 App 页面 | 把 App 页面等比放大到 Web |
| 5 | 多主行动 | 一屏多个同等重量的主按钮 |
| 6 | 信息层级缺失 | 结论、行动、证据混在一层 |
| 7 | 空数组伪装完成 | 接口失败展示为"暂无数据"或 0 |
| 8 | 伪利润 | 成本不完整时展示利润或毛利率 |
| 9 | 前端造状态 | 用本地布尔或前端推导实现"完成" |
| 10 | 新增 Web 专属 API | 为 Web 单独开后端接口 |
| 11 | 专业列表当主入口 | 台账/流水/项目库直接占据一级导航 |
| 12 | 装饰掩盖问题 | 用渐变阴影掩盖信息不清 |
| 13 | 不可键盘操作 | 关键路径无法纯键盘完成 |
| 14 | 只有颜色表达状态 | 状态无文字 |
| 15 | 页面身份重复 | 标题重复三次以上 |

## 13. 页面交付门禁

### G1 业务与场景（编码前）

- [ ] 2 个真实场景（使用人/触发/前置/动作/系统下一步/异常）
- [ ] 页面生成公式五要素齐全
- [ ] 准入三问有答案
- [ ] 动作与 App 对齐清单（逐条列出 App 对应页面与动作）
- [ ] 用到的 Provider 路由可指向 App 调用点（无新增 API）
- [ ] 权限正向 + 负向用例
- [ ] 金额/成本口径与 `costComplete=false` 表达
- [ ] 可完成状态投影（key/label/required/完成条件/异常态）

### G1.5 交互与构图（编码前）

- [ ] 页面原型（六类之一）
- [ ] 唯一主行动
- [ ] 信息层级 ≤3 层
- [ ] 1440 / 1280 / 1024 三档布局说明
- [ ] 全部状态设计（第 6 章）
- [ ] Web 提升点（批量/对账/并行/键盘/密度，至少一项）
- [ ] 复用组件清单

### G2 工程（提交前）

- [ ] 类型检查与构建通过
- [ ] 无 `any`、无静默兜底
- [ ] 无裸色值/裸字号/裸圆角
- [ ] 无 Web 专属 API

### G3 渲染（交付前）

- [ ] 真实浏览器三档分辨率截图（1440/1280/1024）
- [ ] 至少一条关键路径纯键盘完成
- [ ] 控制台无未处理错误
- [ ] 正向与负向权限均已验证
- [ ] 至少两轮「渲染 → 批判 → 修正」

> 未过 G3 不得表述为「页面已完成」。
