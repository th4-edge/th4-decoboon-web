# Web 业务对象专用选择器规范

> 上位依据：装得清业务智能体 `DEC-021`、`DEC-023`、`BR-019`、`BR-021`、`ANS-BIZ-20261007-004`、`ANS-BIZ-20261007-006`
> 研发门禁：先填写 `T15-业务概念选择器设计评审单`，取得 `T06/T12` 后再进入产品规划和研发。
> 原则：选择机制统一，业务模型各自表达。

## 1. 架构

不构建一个统一业务对象选择器。低层只允许存在“远程选择壳”，负责：

- 打开/关闭、搜索、分页、加载更多；
- 选择、清除、取消；
- 加载/空/失败/重试状态；
- `select(value) | clear` 回传。

业务语义由专用选择器负责：

| 专用选择器 | 业务模型 |
| --- | --- |
| 项目选择器 | 状态分组、正常/接管、设计师、常用项目、编号、客户、地址 |
| 客户选择器 | 负责人、状态、最近跟进 |
| 房屋选择器 | 客户归属、小区/楼栋/房号、面积、多房屋显式选择 |
| 账务分类选择器 | 一级/二级树、方向、启用状态、路径 |
| 报价分项选择器 | 分类树、品牌/系列/规格、区域、单位、价格、多选数量 |
| 工人/供应商/员工选择器 | 各自必要的身份、状态、业务摘要 |
| 应收/应付选择器 | 项目、类型、到期日、待收/未付、状态 |

## 2. 参考实现

- 项目：对齐 App `subpackages/finance/pages/project-picker.vue`，Web 采用引导式布局：
  - 左侧责任维度：门店、设计师、项目经理；
  - 顶部经营维度：项目状态、项目来源；
  - 主区：项目卡片，标注金额、状态、来源、设计负责人、施工负责人、当前阶段；
  - 精细搜索只作补充。
- 报价分项：复用并对齐 Web `src/views/designer/components/DesignCatalogPicker.vue`。
- 账务分类：树形展示 `LedgerCategory.children`，不得 flatten 成普通列表。
- 客户+房屋：遵循 `DEC-002`，多房屋必须显式选择。

## 3. 统一机制

- 打开专用选择器；
- 业务特定搜索、过滤、分组或树展开；
- 服务端分页和权限过滤；
- 选择或清除；
- 原表单重新读取并清除失效依赖；
- 服务端保存时再次校验。

## 4. 组件边界

- `RemoteSelectionShell.vue`：只提供远程选择通用生命周期，不定义项目/分类/报价分项等业务字段。
- 业务选择器可以使用该壳，也可以像 `DesignCatalogPicker.vue` 一样自行实现专用交互。
- 禁止把树结构、多选数量、项目状态分组等业务特征强行压成同一组 `label/description` 列表。

## 5. Web 中文

Element Plus 必须在应用层配置 `zhCn` locale。日期、月份、星期、日期范围占位、分页器、Dialog/Drawer 默认文案必须是简体中文。

## 6. 表单分区

- 业务对象选择区使用全宽上下文卡片，不参与左右半栏。
- 金额、日期、账户、类型等短字段可双列。
- 项目、客户、房屋、应收应付、长文本和备注必须占整行。
- 已选项目卡片展示名称、编号、状态、合同金额、设计负责人、施工负责人和当前阶段。
- 表单按“业务对象选择区 → 短字段区 → 结果预览/确认区 → 主行动区”组织。
- 结果区只展示当前提交会产生什么结果，不重算正式金额。

## 7. 单据化表单

有稳定单据形态的动作，直接以最终业务对象作为可编辑主界面，不再重复构造字段表单和预览。应收节点、应付单、收款、付款、合同变更、凭证模板优先采用。上下文、参考数据和风险侧栏按业务对象组织；服务端校验、权限和状态机不变。

## 8. 业务单据视觉层级

- 已选业务对象卡必须满宽且左右信息区对称。
- 长名称可换行，但不得挤压金额、负责人、阶段和操作。
- 常规单选/多选使用传统 select/multi-select；应收类型等单据核心类型可放在节点名称下方，使用紧凑 checkbox 视觉组并保持单值。
- select 仅用于远程对象、长列表和搜索型字典。
- 颜色按表单区域整体渐变呈现；输入项和普通字段保持中性。
- 状态标签可使用状态色，颜色不替代文字。

## 9. 存量治理

新页面立即执行。存量重点审计：

- 远程业务对象直接绑定 `el-select`；
- 树形分类被扁平化；
- 多房屋客户默认第一套房屋；
- 页面初始化一次拉取大列表；
- 通过放大 `size` 代替服务端搜索。
