## 迁移规则

1. 存量页面不得因为“已经能用”就视为符合新规范；必须逐项回查。
2. 新页面、新工作台、新菜单入口不得新增 `DEF-WEB-*`；必须先进入 `workbench-navigation.json`。
3. 每个迁移项必须绑定角色、主链、对象锚点、页面/路由、证据目录和目标批次。
4. 迁移前只允许只读审计、Provider 映射和 T05/T06/T12 咨询；不得先改状态或权限。
5. 迁移后发现业务口径冲突，停止 Web 单端处理，建立 `GAP-*` 交业务智能体裁决。
6. 迁移完成后必须更新状态、关联知识卡、验收证据和 `workbench-navigation.json` 的 `decisionStatus`。
7. 未关闭的 `DEF-WEB-*` 不得用“全角色沉浸式闭环已完成”或类似结论掩盖。

- [ ] `actionPolicyKeys` 可追溯到动作注册表；
- [ ] `reloadScopes` 完整；
- [ ] 未保存草稿、筛选、滚动、版本和深链接可恢复；
- [ ] 多入口进入同一对象事实一致；

- [ ] `check:workbenches`、`check:workspaces` 和页面验收通过。

## 关闭定义

一个 `DEF-WEB-*` 只有同时满足以下条件才能关闭：

- 对应页面/工作台已登记 `workbench-navigation.json`；
- 真实浏览器完成多入口、零搜索进入、完成后交接和上下文恢复验证；
- 权限、金额、成本、利润和审计负向用例通过；
- 关联业务事实、知识卡和验收证据已回写；
- 产品规划、研发和独立验收均无未解决阻断。
