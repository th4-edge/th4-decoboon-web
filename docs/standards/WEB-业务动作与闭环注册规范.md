# Web 业务动作与闭环注册规范

> 状态：生效并强制执行  
> 适用范围：状态推进、单据保存、审批、确认、驳回、收付款、撤销、重开等业务动作  
> 上位依据：`BR/DEC` 业务规则、`WEB-业务状态机与闭环一致性规范.md`

> 动作权限和数据范围还必须遵循 `docs/standards/WEB-业务指标与权限注册规范.md`。

---

## 1. 目标

状态机定义“当前状态、允许状态和投影关系”，动作注册定义“谁能做、何时能做、做完变成什么、完成后要刷新什么”。

每个业务动作必须同时绑定：

```text
业务对象
-> 服务端 Provider
-> 角色与数据范围
-> 前置条件
-> 源状态
-> 目标状态
-> 幂等策略
-> 审计要求
-> 关联刷新范围
-> 失败恢复
```

页面按钮只能消费服务端动作策略，不能在页面自己拼接规则。

---

## 2. 动作注册表

机器可读文件：

```text
docs/standards/business-action-policies.json
```

每个动作必须包含：

| 字段 | 含义 |
| --- | --- |
| `key` | 稳定动作键，如 `receipt.create` |
| `label` | 业务动作中文名 |
| `object` | 主业务对象 |
| `provider` | 服务端 Provider 路由 |
| `roles` | 允许角色 |
| `scope` | Company/Store/Team/Self/ProjectParticipant |
| `from` | 允许的源状态；不适用时为空数组 |
| `to` | 成功后的目标状态；不适用时为空 |
| `preconditions` | 前置条件 |
| `idempotency` | 幂等要求 |
| `confirmation` | 二次确认要求 |
| `audit` | 审计留痕要求 |
| `reloadScopes` | 成功后需要回读的业务对象 |
| `moneyImpact` | 是否影响金额、成本、应收、应付或利润 |
| `failureRecovery` | 失败后的恢复路径 |
| `decisionStatus` | `frozen` 或 `pending_business_review` |
| `businessRefs` | 业务规则编号 |

---

## 3. 动作与状态机的关系

规则：

1. `from` 和 `to` 必须引用状态机注册表中的真实状态。
2. 动作声明会影响哪些对象，这些对象必须存在于状态机或业务概念注册表。
3. 状态机 `actionPolicy` 中出现的动作，必须能在动作注册表中找到。
4. 动作标记 `frozen` 后，必须完整声明角色、前置条件、幂等和刷新范围。
5. 业务规则未裁决的动作只能标记 `pending_business_review`，不得由前端猜测。

---

## 4. 闭环刷新契约

动作成功后不得只刷新当前页面对象。必须按 `reloadScopes` 回读关联事实：

| 动作 | 必须回读 |
| --- | --- |
| 量房完成 | 房屋、客户派生标签、设计下一步 |
| 报价提交/接受/驳回 | 报价、设计、合同交接、项目立项前置 |
| 合同生效 | 合同、项目、应收计划、财务 |
| 合同变更客户确认 | 变更、合同、任务、材料、应收、成本 |
| 收款登记 | 应收、收款、资金台账、项目回款 |
| 付款登记 | 应付、付款、资金台账、项目成本 |
| 阶段验收确认/驳回 | 验收、阶段、任务、项目状态 |

若某个关联对象读取失败，页面必须显示“部分数据暂不可确认”，不得用旧值伪装成功。

---

## 5. 权限与幂等

### 权限

- 前端 `allowedActions` 只控制可见性和即时反馈；
- 服务端仍按登录员工、企业、门店、团队、项目和对象归属重新校验；
- 不得信任前端传入的 `companyId/empId/ownerId`。

### 幂等

以下动作必须提供幂等键或服务端幂等策略：

- 收款；
- 付款；
- 审批；
- 客户确认；
- 验收确认/驳回；
- 冲正和重记。

---

## 6. 自动门禁

新增命令：

```bash
npm run check:actions
```

检查：

- 动作注册字段完整；
- `object/from/to/reloadScopes` 引用有效；
- 状态机 actionPolicy 均有动作注册；
- `frozen` 动作必须具备角色、前置条件、幂等和恢复路径；
- 金额动作必须声明 `moneyImpact` 和账务刷新范围；
- 不允许状态机出现未注册的业务动作。

- [ ] Provider、角色和数据范围已明确；

- [ ] 幂等、二次确认和审计策略已明确；
- [ ] 关联刷新范围已声明；
- [ ] 页面只消费服务端动作策略；
- [ ] `npm run check:actions` 通过；
- [ ] 真实浏览器验证动作完成后的跨对象状态一致。
