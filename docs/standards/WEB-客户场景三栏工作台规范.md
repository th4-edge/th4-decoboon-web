# Web 客户场景三栏工作台规范

> 状态：生效并强制执行（2026-10-09）
> 适用页面：设计师「待我跟进」「待我量房」「客户诉求」及后续客户/房屋场景队列工作台
> 上位依据：`DEC-033` / `BR-029`、`DEC-034` / `BR-030`、`BR-005`、`SCN-014`、`SCN-017`
> 业务事实源：全局 `zhuangdeqing-business`；本文不新增或修改业务对象、状态、动作、权限和金额口径。

---

## 1. 核心结构

客户/房屋类场景工作台统一采用：

```text
左栏：客户 / 房屋队列
中栏：选中客户 / 房屋对象工作面
右栏：状态原因 + 唯一主行动 + 完成回读 + 下一接棒
```

三栏共同回答三个问题：

1. 现在有哪些对象需要我处理？
2. 当前选中的客户和房屋真实事实是什么？
3. 为什么现在处理、允许做什么、完成后去哪里？

---

## 2. 左栏：客户 / 房屋队列

- 只展示当前角色、当前数据范围、当前场景入站状态内的对象。
- 列表项必须同时表达客户身份和房屋锚点；没有房屋时明确显示“房屋待补充”，不得伪造房屋。
- 进入量房、设计、合同、施工等房屋执行阶段时，使用者视角以房屋为主对象：左栏卡片第一视觉层级展示房屋名称、地址/小区、面积/户型，客户姓名与电话降为归属信息。
- 量房工作台左栏不得展示操作引导、主行动或完成回读；这些统一放入右栏，避免列表同时承担队列和操作说明。
- 排序、风险原因和在途状态以服务端聚合/投影为准；前端只做已裁决的筛选切换。
- 当前选中项必须高亮，选中后不得重新搜索同一客户。
- 空态必须说明为什么为空、如何恢复或刷新，不得只显示“暂无数据”。

## 3. 中栏：客户 / 房屋对象工作面

- 顶部固定显示客户身份、客户阶段、风险、电话和房屋摘要。
- 客户与房屋为共同锚点；多房屋必须显式选择 `activeProperty`，未选择时显示选择提示，不得默认第一套。
- 中栏只承载当前场景需要的事实，例如跟进记录、房屋状态、量房事实或诉求事实。
- 不得在中栏复制右栏的主行动、阻断原因和完成后交接。
- 客户详情中的房屋与最近沟通必须上下排列，不以压缩关键信息为代价强行左右并排。
- 房屋卡必须提供编辑和删除操作；删除前确认，是否允许由服务端按量房、诉求、方案、报价、合同和项目事实最终裁决，前端不得自行推断可删除。
- 客户经营操作统一使用右侧抽屉承接表单，不混用弹窗和抽屉；抽屉顶部先展示客户/房屋上下文，再展示录入区、风险/结果说明和唯一主行动。
- 待跟进主链的核心业务动作是“预约量房”，不得把“建立房屋”当作独立结果动作展示；没有房屋时，应在预约量房抽屉内先建立房屋，再选择或填写量房时间。
- 预约量房成功后，必须进入待我量房工作台，并用 `customerId + activePropertyId` 自动定位本次预约客户和房屋。
- 待我跟进和待我量房必须复用同一套“设为休眠客户”右抽屉；业务员、店长、企业负责人和设计师可见，原因和状态门禁由服务端最终裁决。
- 客户基础资料必须在当前起点页面内可编辑，复用客户 update Provider，不通过普通编辑静默修改负责人。
- 客户画像必须在当前起点页面内可编辑，按“需求与计划 / 偏好与预算 / 决策参考 / 主要顾虑”分区展示；主要顾虑使用可见 checkbox 多选，禁止使用下拉多选。

## 4. 右栏：状态引导

右栏固定按以下顺序组织：

1. **为什么现在处理**：显示服务端风险原因、到期状态或入站原因。
2. **唯一主行动**：只突出一个主按钮；服务端未允许时禁用并显示阻断原因。
3. **完成后的回读**：列出动作成功后必须重新读取的客户、房屋、跟进、工作台等范围。
4. **其他合法动作**：联系客户、打开客户 360、进入下一场景等，降级为次级按钮。
5. **下一接棒**：显示完成后去向、下一状态和下一位责任人；没有下一对象时显示空态。
6. **下一项切换**：只能由用户显式点击，动作完成后不得自动切换客户。

## 5. 客户 Hero 与信息融合

> 客户 Hero 是《WEB-工作台设计构建规范》§4.7「对象 Hero 家族」的一个实例：
> 统一使用共享组件 `CustomerHeroCard`（骨架 + 客户主体配置），**不得另写一套 Hero**。
> L1 当前阶段关注层由各页插槽传入（跟进页 = 下次联系 / 最近沟通）。

客户经营起点页只保留以下主要视觉块：

```text
客户 Hero
房屋 + 最近沟通
状态引导 + 客户操作
```

客户 Hero 必须融合：

- 客户姓名、客户阶段、风险、客户评级、评分等级色；
- 电话、来源、小区/地址、面积、预算、负责人、设计师；
- 是否加微信、到店次数、最近到店、客户标签摘要；
- 客户画像摘要，并支持在当前页面直接完善画像；
- 至少保留一个“完整档案”次级入口，但不得把完善画像、写跟进、记录微信、记录到店等当前起点动作强制转到客户 360。

客户 360 和待我跟进都是合法起点，不是上下游关系；进入任一页面都应能在本页完成该起点负责的动作。客户 360 只承载完整档案和历史低频信息，不作为待我跟进的强制中转站。

## 6. 首屏与操作密度

- `1440 × 900`、`1280 × 800/900` 下，左队列、中客户 Hero/房屋/最近沟通、右主操作和全部关键操作必须在一个屏幕内可见。
- 客户 Hero 内部通过摘要、展开和分组承载信息，禁止把每个字段拆成独立卡片。
- 右侧只保留一个主行动和一组操作，不再拆分“建议 / 回读 / 其他动作 / 下一项”多个长卡片。
- 客户列表可内部滚动，但页面关键操作不得因列表增长被推到首屏之外。
- 操作按钮统一使用图标 + 标题；主操作、次要操作、提醒操作、恢复操作使用不同语义色。

## 7. 操作颜色标准

| 层级 | 颜色 | 用途 |
| --- | --- | --- |
| 主操作 | 品牌实色 `$brand-600` | 写跟进、保存等唯一下一步 |
| 沟通操作 | 品牌浅底 + 品牌图标 | 打电话、微信 |
| 记录操作 | 绿色/橙色浅底 + 语义图标 | 记录到店、记录微信等事实动作 |
| 普通次级 | 白色底 + 灰色边框 | 完整档案、低频入口 |
| 提醒操作 | 橙色底/橙边 | 设为休眠、暂不跟进 |
| 恢复操作 | 绿色底/绿边 | 恢复跟进、恢复可用状态 |
| 危险操作 | 红色 | 删除、不可逆操作；客户经营页不得滥用 |
## 8. 客户信息层

客户经营类工作台中栏必须先展示客户是谁、怎么联系、沟通到了什么程度，再展示流程动作：

1. **基本信息**：电话、来源、小区/地址、面积、预算、客户等级、客户负责人、负责设计师。
2. **关系事实**：是否已加微信、微信号、到店次数、最近到店时间。
3. **客户画像**：装修目的、房屋状况、开工窗口、风格偏好、环保要求、家庭结构、付款方式、竞品对比、关注点；未填写时明确显示“未填写”，不得编造。
4. **客户标签**：展示系统标签和人工标签；标签为空时说明标签会随真实业务动作自动产生。
5. **最近沟通**：展示最近跟进记录、跟进方式、时间和下次联系时间。

客户信息属于高频决策上下文，不得藏在二级弹窗或客户 360 才可见；客户 360 继续承载完整档案和低频字段。

## 9. 动作与文案层级

右栏动作必须按使用者语言组织，不出现“服务端、对象锚点、主链、回读、队列”等研发术语。

- 主行动：写跟进。
- 沟通动作：打电话、记录加微信/更新微信、记录到店。
- 客户动作：打开完整档案、预约量房；没有房屋时在预约量房抽屉内建立房屋。
- 状态动作：设为休眠客户、恢复跟进。业务员、店长、企业负责人和设计师可见；其他角色不显示越权入口。
- 动作说明用一句话回答“什么时候用、会产生什么结果”，例如“客户已经加微信时登记”“已到店时记一次”。

完成后文案面向使用者说“保存后会更新哪些客户资料”，不使用“回读范围”“服务端状态”等内部表达。

## 10. 状态与动作来源

- 客户状态、风险等级、风险原因、下一步动作必须消费服务端投影。
- 右栏主行动必须与服务端允许动作一致；前端不得按日期、阶段文案或按钮点击结果自行推导状态机。
- 页面筛选如果依据 `nextFollowAt` 等原始时间事实，只能用于队列呈现，不得改写服务端状态和完成条件。
- 部分读取失败时显示“部分数据暂不可确认”，保留已成功区域和恢复路径。

## 11. 响应式规则

| 宽度 | 布局 |
| --- | --- |
| `> 1400px` | 左 / 中 / 右三栏同屏，右栏可吸顶 |
| `1025px–1400px` | 左 + 中两栏，右栏移到中栏下方全宽展示 |
| `<= 1024px` | 左、中、右依次单列，队列和引导取消吸顶 |

任何宽度都必须满足：

- 无横向溢出；
- 客户、房屋、状态和唯一主行动在上方可见区域内；
- 键盘可聚焦所有可点击项；
- 屏幕阅读器可读出当前选中对象、主行动、阻断原因和完成去向。

## 12. 强制回读

| 动作 | 至少回读 |
| --- | --- |
| 写跟进 | 客户、客户跟进、工作台队列 |
| 建房屋 | 客户、房屋、量房可用性 |
| 安排量房 | 客户、房屋、量房、待办队列 |
| 登记量房 | 房屋、客户派生标签、设计可用性 |
| 进入下一场景 | 当前对象 + `activeProperty` 上下文保持一致 |

任一回读失败不得使用旧值、空数组或本地布尔值伪装成功。

## 13. 反模式（一票否决）

1. 左栏只列客户、不表达房屋锚点。
2. 中栏和右栏重复主行动，用户无法判断唯一下一步。
3. 未选房屋时默认第一套房屋。
4. 右栏按客户阶段文案自行拼状态机或权限。
5. 动作完成后自动切换客户，导致用户不知道刚才操作了谁。
6. 刷新/返回/深链接丢失 `customerId` 或 `activePropertyId`。
7. 用“暂无数据”“0”覆盖读取失败或部分确认。
8. 三栏同屏造成叠加滚动、遮挡或横向溢出。

## 14. 交付定义

- [ ] 左栏队列有入站状态、排序和空态；
- [ ] 中栏客户与房屋锚点显式；
- [ ] 右栏原因、唯一主行动、回读和接棒完整；
- [ ] 多房屋显式选择，上下文可恢复；
- [ ] 完成动作后按 `reloadScopes` 回读；
- [ ] 1400 / 1280 / 1024 三档真实浏览器无横向溢出；
- [ ] `check:workbenches`、`check:workspaces`、`check:page-system` 通过。
