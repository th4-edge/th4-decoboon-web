## GAP-WEB-001 · 业主确认主体口径不一致

### 现象

App 两份产品设计对「客户确认」的主体口径相反：

| 来源 | 口径 |
| --- | --- |
| `docs/product/2026-09-21-合同增减项业务流程与交互设计.md` §2.5 | **客户不登录小程序**（2026-09-21 已确认）；客户确认由项目经理/负责人**现场代登记**（拍照 + 签名），不开放客户自助入口 |
| `docs/product/2026-09-21-阶段验收整改闭环业务流程与交互设计.md` §2.3 | 业主确认 / 驳回 **仅业主本人**（授权会话）；**员工不得代录** |
| `docs/02-闭环页面逻辑与高保真视图.md` 链路 D | 业主打开「我的家」查看验收单并点确认/驳回（业主本人操作） |

### 影响

- Web 是否实现业主确认入口、由谁代登记、是否需要业主会话，取决于此裁决。
- 涉及业主身份、邀请、会话、权限与审计留痕，属高风险口径。

### 待裁决问题

1. 业主确认在不同业务对象（变更 / 验收）上是否**允许不同主体**？如果允许，边界如何表述？
2. 若统一为「业主本人确认」，增减项的现场代登记如何处置（保留为代录还是取消）？
3. 若统一为「可代登记」，验收环节的业主授权与责任如何保证？

### 处置

- 状态：`OPEN`，等待调用 `zhuangdeqing-business` 裁决。
- 关闭前：Web **不得实现任何业主确认入口**，也不得在文档中假定其中一种口径。
