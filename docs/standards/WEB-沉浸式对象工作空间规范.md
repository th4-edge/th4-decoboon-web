# Web 沉浸式对象工作空间规范

> 状态：生效并强制执行（2026-10-07）
> 上位依据：`DEC-033`、`BR-029`、`DEC-002`
> 业务事实源：全局 `zhuangdeqing-business`；本文不新增、不修改业务对象、状态、动作、权限、金额、成本或利润口径。
> 适用范围：Web 对象工作空间、对象身份条、当前工作面、状态动作面板、上下文恢复、全屏工作区和安全门。

---

## 1. 核心定义

沉浸式操作不是“所有功能塞进一个页面”，而是：

> 以业务对象为锚点，以服务端状态视图和动作策略为驱动，把当前角色在当前状态下需要的事实、唯一主行动、前置条件、阻断原因、责任人和完成后影响放在同一连续上下文内；能在对象上下文内安全完成的优先就地完成，复杂操作进入保留上下文的受控工作面，高风险动作进入受控安全门。

“不切换页面”精确化为：

> 不重新搜索同一对象，不重建业务上下文，不丢失当前房屋/项目/版本/草稿/筛选/滚动位置；页面路由、全屏工作区和安全门可以存在，但不得造成上下文断裂。

## 2. 对象工作空间组成

```text
对象工作空间 =
  对象身份条
  + 对象主线
  + 当前工作面
  + 状态动作面板
  + 上下文恢复机制
```

| 组成 | 要求 |
| --- | --- |
| 对象身份条 | 固定显示对象身份、状态、负责人、数据范围、关键金额/风险和对象切换入口 |
| 对象主线 | 展示客户、房屋、方案、报价、合同、项目、阶段等真实对象关系；不得新增状态 |
| 当前工作面 | 只显示当前状态需要处理的业务面板 |
| 状态动作面板 | 消费服务端状态视图和允许动作，展示下一步、原因、责任人、前置条件、阻断原因和完成后状态 |
| 上下文恢复 | 深链接、刷新、返回、筛选、滚动、`activeProperty`、版本和草稿恢复 |

## 3. 对象锚点规则

1. 客户主线：客户 + `activeProperty`；多房屋必须显式选择。
2. 项目主线：项目 + 当前阶段/当前任务/当前单据。
3. 财务主线：项目 + 应收应付/收付款/台账/凭证对象。
4. 风险/待办队列：队列 + 选中对象。
5. 对象锚点必须写入路由、深链接和上下文恢复状态。
6. 未指定锚点时不得默认第一条；显示待认领、待选择或待补充。

## 4. 状态与动作规则

1. 页面只消费服务端状态视图和允许动作，不写前端业务状态机。
2. 每个状态只有一个视觉最重的主行动；其余动作降级。
3. 规则未命中、状态未映射、对象关系不成立时显示“待业务确认”，主行动禁用。
4. 合同 `Signed` 与 `Effective` 必须区分；只有 `Effective` 可以进入项目。
5. 报价 `Submitted` 显示“待客户决策”；`Draft` 不进入正式轨道结果；`Superseded` 只显示历史。
6. 客户 `Lost/Finished`、合同 `Terminated/Closed` 等终态必须保留展示。
7. 成本/利润可见性按既有权限裁剪；无权限角色不生成相关区块。

## 5. 操作层级

| 层级 | 适用 | 强制要求 |
| --- | --- | --- |
| L0 就地操作 | 低风险、单字段或低复杂度动作 | 对象身份条保持可见；失败就地恢复 |
| L1 上下文抽屉/面板 | 多字段表单、附件、对象选择、可逆动作 | 继承对象锚点；关闭后恢复焦点和滚动 |
| L2 全屏工作区 | 报价编辑、版本对比、批量维护、复杂对账、导入导出 | 保留身份条、深链接和返回上下文；不得成为孤立页面 |
| L3 安全门 | 合同正式生效、收付款结算、退款/冲正、审批、删除、权限变更、批量改价/成本影响、跨租户动作 | 必须前置校验、二次确认、幂等、审计和失败恢复；安全门不改变对象上下文 |

## 6. 上下文连续规则

1. 切换对象、打开全屏或进入安全门前有未保存草稿时，必须提供保存后切换、放弃并切换、取消三条路径。
2. 刷新、浏览器前进后退、深链接必须恢复对象 + 子对象 + 工作面 + 必要筛选。
3. 连续处理下一项必须由用户显式触发；不得在动作完成后自动切换对象。
4. 关闭抽屉/全屏/安全门后，焦点、滚动位置和筛选必须恢复到进入前。
5. 禁止抽屉叠抽屉、对话框叠对话框。
6. 不得用空数组、旧值或 0 伪装完成。

## 7. 闭环回读

动作成功后必须按 `reloadScopes` 回读：

| 动作示例 | 必须回读 |
| --- | --- |
| 量房完成 | 房屋、客户派生标签、设计下一步 |
| 报价提交/接受/驳回 | 报价、设计、合同交接、项目立项前置 |
| 合同生效 | 合同、项目、应收计划、财务 |
| 合同变更客户确认 | 变更、合同、任务、材料、应收、成本 |
| 收款登记 | 应收、收款、资金台账、项目回款 |
| 付款登记 | 应付、付款、资金台账、项目成本 |
| 阶段验收确认/驳回 | 验收、阶段、任务、项目状态 |

任一回读失败，页面显示“部分数据暂不可确认”，不得用旧值或空数组伪装成功。

## 8. 反模式（一票否决）

1. 把所有功能塞进一个巨型页面。
2. 用 Tab 平铺取代页面切换。
3. 有对象详情，无对象身份条和当前工作面。
4. 有按钮，无唯一主行动和完成后状态。
5. 前端自算状态、权限、金额、成本、利润或完成度。
6. 动作完成后只刷新当前卡片，不执行 `reloadScopes`。
7. 没有深链接、刷新恢复或未保存草稿保护。
8. 无权限角色仍生成成本/利润区块。
9. 高风险动作绕过确认、幂等或审计。
10. 用“待确认/暂不可确认”之外的方式伪装完成。

## 9. 自动门禁

必须运行：

```bash
npm run check:workspaces
```

检查内容：

- 对象锚点、当前工作面、唯一主行动、完成后交接完整；
- 上下文恢复字段完整；
- 未保存草稿保护策略明确；
- `reloadScopes` 非空；
- 工作台注册表中的对象工作空间契约完整；
- 与 `check:workbenches`、`check:states`、`check:actions` 联合通过。

## 10. 交付定义

- [ ] 对象锚点显式且可恢复；
- [ ] 状态视图和允许动作来自服务端；
- [ ] 唯一主行动、前置条件、阻断原因和完成后状态清楚；
- [ ] 上下文恢复和草稿保护完成；
- [ ] 动作后 `reloadScopes` 验证通过；
- [ ] 高风险动作保留确认、幂等和审计；
- [ ] 多入口进入同一对象事实一致；
- [ ] 真实浏览器验证正常、拒绝、越权、并发、部分确认和三档分辨率。
