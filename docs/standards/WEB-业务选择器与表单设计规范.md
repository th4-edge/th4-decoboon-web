## 2. 核心原则

### 2.1 一致性有尺度

必须统一：

- 字段和业务对象含义；
- 选择、清除、回传和服务端复核语义；
- 状态、错误、空态和恢复路径；
- 权限和数据范围；
- App/Web 对同一业务事实的口径。

可以不同：

- 控件宽度和占列；
- 选择器布局；
- App/Web 交互形态；
- 卡片、树、级联、表格、单据等视觉结构。

### 2.2 数据先展示，搜索后辅助

业务选择器打开后应优先展示可判断数据，不允许只给搜索框或空白下拉。搜索是精确定位手段，不是唯一导航。

### 2.3 业务对象按自身模型表达

- 项目：责任维度、状态、来源、金额、负责人、阶段。
- 客户+房屋：客户和多房屋上下文，禁止第一套房屋兜底。
- 账务分类：树形层级、方向、启停和完整路径。
- 报价分项：分类树、品牌/系列/规格、区域、价格和数量。
- 工人、供应商、员工、应收、应付：各自显示业务判断所需标签。

### 2.4 表单就是业务结果

有稳定单据形态的动作，优先以最终业务对象作为可编辑主界面。字段表单和预览区不得重复表达同一事实。

### 2.5 颜色按区域表达

- 表单主体和参考侧栏可以使用柔和渐变。
- 输入项、金额字段、日期字段、普通指标卡保持中性。
- 状态标签、风险提示可使用状态色。
- 禁止逐字段、逐指标使用不同颜色。

### 2.6 控件密度服从任务

- 普通单选、多选：传统 `select` / `multi-select`。
- 单据核心类型：可使用节点名称下方的紧凑 checkbox 视觉组，但保持单值语义。
- 远程业务对象：专用选择器。
- 展开式大卡片仅用于选项极少且选择本身是主任务的场景。
- 不得用大块控件挤压表单空间。

### 2.7 服务端是最终裁决

前端组织事实、展示上下文和即时校验；金额、成本、利润、状态、权限和归属由服务端最终校验。

## 3. 控件选择决策树

```text
是否是后端固定枚举或稳定封闭字典？
├─ 是
│  ├─ 普通字段：select / multi-select
│  └─ 单据核心类型且选项少：节点名称下紧凑 checkbox（单值）
└─ 否
   ├─ 是否是可配置字典或树？
   │  ├─ 是：专用字典/树选择器
   │  └─ 否：业务对象
   │     ├─ 是否远程、分页、权限过滤？
   │     │  ├─ 是：专用业务对象选择器
   │     │  └─ 否：少量直接可见选项
   │     └─ 选中后是否影响上下文？
   │        └─ 是：全宽上下文摘要卡
```

## 5. 表单分区

```text
1 业务上下文
2 业务对象主录入区 / 单据正文
3 短字段区
4 业务参考 / 风险区
5 主行动
```

规则：

- 项目、客户、房屋等上下文占满宽度。
- 长文本、备注、复合对象占整行。
- 金额、日期、账户、类型等短字段可并排。
- 结果对象是主界面时，不再额外建立重复预览区。
- 参考侧栏只展示服务端事实，不重算正式业务金额。

## 6. 视觉层级

| 层级 | 处理 |
| --- | --- |
| 背景 | 表单主体和参考区域使用柔和渐变 |
| 主对象 | 单据标题区、名称、金额、日期 |
| 状态 | 状态标签、风险提示 |
| 辅助事实 | 客户、地址、负责人、阶段 |
| 输入 | 中性底色、统一边框和焦点 |

禁止：

- 金额、日期、每个指标各一套颜色；
- 用颜色替代文字；
- 大尺寸选择卡挤压表单。

---

## 7. 统一选择机制

所有专用选择器必须统一：

- 打开、取消、选择、清除；
- 搜索、分页、长列表；
- 加载、真实为空、失败、重试、无权限、失效；
- 上下文变化时清理依赖字段；
- 返回对象/引用和展示摘要；
- 保存时服务端重新校验。
