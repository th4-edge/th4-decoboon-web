# 角色评价（本次仅设计师角色真实登录）

## 设计师（董夏鹏）｜ 岗位适配评价

**能做什么（实测）**：客户录入 → 房屋建档 → 量房预约 → 量房结论（含现场照片、尺寸记录、诉求、结论）→ 新建方案 → 区域实测（长宽快照 + 实测面积/周长）→ 从报价项目库选分项（多选、按区域分组）→ 完成设计 → 生成报价草稿 → 提交客户确认；项目阶段可做主材选材、增减项、查看阶段验收。

**体验优点（第一视角）**
- 主链自始至终都有「当前唯一主行动」：完成首次联系 → 预约量房 → 登记量房结论 → 新建方案 → 完成设计 → 生成报价 → 提交客户确认，几乎不需要自己找入口。
- 状态文案专业且一致（待量房 / 已预约·待上门 / 量房完成·待交设计 / 设计中 / 待谈单 / 待客户确认），跨页面同口径。
- 报价项目库与真实报价单同源：拆除门窗 28.8、地砖铺贴 71.3、木门 1080 与附件一致，选完即得金额，设计师可直接复现真实报价（既有 Q1790922936204 ¥126,507.41 ≈ 附件含税 126,507.42）。
- 金额口径可核对：分项=单价×工程量；报价=小计×1.05（5% 税）；方案面积=区域实测面积合计（27.40㎡）。
- 宽屏三档无横向溢出；表格-分组-小计结构清晰。

**第一视角的困惑与卡点**
1. 「完成设计」之后弹窗突然显示 0 个分项、按钮变灰，我第一反应是「我的分项是不是丢了」（XA-001）。
2. 量房/设计抽屉顶部把已有电话、面积、户型写成「待补充/待确认」，让我怀疑自己刚才是不是没保存成功（XA-002）。
3. 现场记的客户诉求，回到页面却提示「还没有诉求记录」，设计时还要再录一遍（XA-005）。
4. 9 个区域要开 9 次窗、每个都从「客厅」开始改类型，四室户型录下来很累（XA-006）。
5. 提交报价后页面变只读，没有告诉我「下一步谁做什么」，我不知道该去找谁（XA-004）。
6. 「待我签约」里没有任何能推进的动作，「项目工地」的验收提交对我是灰的，感觉我的闭环到报价就断了（XA-004）。

**客观结论**：设计师在 Web 上能独立完成「客户→房屋→量房→设计→报价→提交客户确认」这一段（含金额自动计算与项目库复用），这是本次审计最有价值的确认；但从报价提交到合同/项目/交房必须其他角色介入，且**当前没有把下一责任人显式交给设计师**。

# 多角色推进评价（2026-10-11 05:18–05:30，真实登录）

## 店长（王洪文）｜ 岗位适配评价

**能做什么（实测）**：门店经营工作台本体可用——本店客户、风险队列、整改跟进、客户意见投诉、增减项、主材选材、资金台账均可打开（`/workbench*`、`/finance/ledger` 正常）。

**第一视角卡点**
1. 工作台把「待我签约」「待我谈单」放在最显眼的 P0 位置，我点「进入工作台」后却直接跳到「无权访问该页面」——产品让我做的事情，页面不让我进（XA-013）。
2. 我作为店长是合同复核确认的责任人，但没有任何一个页面能完成确认（XA-012）。

**客观结论**：店长在 Web 上**无法完成被指派的核心动作**（合同确认签约/生效），门店经营链在主链上断裂；这不是数据范围问题（服务端 `requireContractConfirmer` 明确包含 StoreManager），而是入口与前端守卫的错配。

## 企业负责人（张伟）｜ 经营视角评价

**能做什么（实测）**：经营管控中心、待我签约、待我谈单、待收款/待付款、资金台账、风险队列入口齐全；能看到全企业 24 个签约任务与待企业确认合同。

**第一视角卡点**
1. 打开待企业确认的合同，唯一主行动就是灰掉的「待企业确认签约」，我不知道该在哪里点确认（XA-012）。
2. 合同生效生成项目后，项目没有项目经理，我在 Web 上找不到指派入口（XA-016）。
3. 项目阶段计划一生成就写着「开工交底：本项不涉及」，而项目经理页面又把它当成当前阶段，双方口径对不上（XA-014/XA-015）。

**客观结论**：负责人在 Web 上只能「看」不能「批」，经营管控中心缺少合同确认与项目成员指派这两个关键批处理动作；对一个「经营工作台」来说这是能力缺口而非体验瑕疵。

## 项目经理（徐勇）｜ 岗位适配评价

**能做什么（实测，PASS）**：项目列表按本人负责过滤正确；任务可「开始任务 → 提交验收 → 完成任务」并强制上传现场证据（0/12 计数、必填校验生效）；阶段验收可提交「验收说明 + 现场证据」，形成第 1 轮 Pending 记录，并明确「确认或驳回必须业主本人」。

**第一视角卡点**
1. 新项目一开始不在我的列表里（没有指派项目经理），我是被负责人指派后才看到的（XA-016）。
2. 主行动「开启阶段」点了就报「该阶段已判定为本项不涉及，请先撤销判定再开工」，我在 Web 上找不到撤销的地方，也不知道该做哪个阶段（XA-014）。
3. 页面一边写「当前只读」，一边又给可点的按钮；验收提示还写「设计师可提交验收」，实际是我提交（XA-018）。

**客观结论**：PM 的**任务与阶段验收提交**在 Web 上是可用的（这是本次最有价值的确认之一），但**开工入口被状态枚举与计划生成拖死**，导致他只能绕过「开工」直接推进任务与验收。
