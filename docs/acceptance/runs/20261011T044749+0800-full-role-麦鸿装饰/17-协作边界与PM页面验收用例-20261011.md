跨边界规则：
1. 同一文件同一时间只允许一方持有编辑权；需要越界改动时先写入本文件「越界登记」小节并知会对方。
2. 任一方提交前必须跑 `npm run type-check` 与 9 项 `check:*`；`build` 在合并批次前跑一次。
3. 后端 `com.th4.edge.decoboon.project.*`（阶段/项目/验收）由本会话负责的后端改动需先登记（见下）。

## 二、共享契约（双方必须一致）

1. **阶段状态值**：后端 `StageStatus` 枚举值为 `Todo / Doing / Accepting / Done / Cancelled / NotApplicable`；前端 `StageStatus` 必须包含 `notApplicable`，映射 `NotApplicable → notApplicable`（不得再用 `?? 'todo'` 兜底）。
2. **「本项不涉及」语义**：由后端 `ProjectContext` 自动判定（无合同施工行）；撤销必须走 `project/stage/update`（status=`Todo` 分支，GAP-039 / DEC-057），撤销后阶段回到待开始、可正常开工。
3. **项目经理指派**：`project/project/update` + `managerId`；后端校验候选人 `role ∈ {Pm, Boss}`；指派成功必须留痕（现有实现写 `ProjectReport` 变更记录）。合同生效生成项目时 `manager` 仍为空（见 XA-016），前端指派入口不得跳过该接口直接改库。
4. **验收与业主确认**：员工侧只能提交验收（`project/acceptance/save`）；确认/驳回必须业主本人在小程序授权会话执行，员工侧 `project/acceptance/update` 一律 403——PM 页面不得出现「代业主确认」按钮。
5. **金额口径**：阶段/验收/成员指派不得读写成本、利润、应收应付金额字段（仅财务与负责人可见）。

## 三、PM 页面验收用例（本会话复验时逐条执行）

| # | 用例 | 期望 |
| --- | --- | --- |
| R1 | 项目被系统判定「本项不涉及」（如新项目开工交底） | 阶段卡片显示「本项不涉及」且**不提供**「开启阶段」；主行动改为「撤销本项不涉及」 |
| R2 | 点「撤销本项不涉及」 | 二次确认 → 阶段回到「待开始」→ 可正常「开启阶段」；操作后按 `reloadScopes` 回读，失败显示「部分数据暂不可确认」 |
| R3 | 反向：非「不涉及」阶段 | 不出现撤销入口；「开启阶段」只在阶段为待开始时可用 |
| R4 | 合同生效生成的新项目 | 项目经理为空时**必须**能明确看到「未指派项目经理」并有一条指派入口（不得静默显示为可推进） |
| R5 | 指派项目经理 | 候选人仅 Pm/Boss；指派后项目出现在该 PM 的「我的项目」；留痕可查 |
| R6 | 指派的越权校验 | 非授权角色调用 `project/project/update(managerId)` → 403；跨门店对象不可见 |
| R7 | 阶段验收 | 任务未全部完成 → 不允许提交；提交后形成轮次记录；业主确认按钮不可用 |
| R8 | 三档分辨率 | 1440x900 / 1280x800 / 1024x768 无横向溢出，无控制台 error |
