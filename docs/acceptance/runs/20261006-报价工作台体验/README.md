## 四、自动保存状态迁移

```text
已同步 → 有未保存改动（1 行）→ 保存中 → 已保存 → 已同步
```

- 仅在 `Draft` 生效；停止编辑 **1.2s** 后触发
- 保存中继续编辑 → 排队（`pendingSave`），不丢最后一次输入
- 成功后重新拉取服务端并清脏
- 失败保留编辑内容 + 显示可重试错误
- **非法值（工程量/价格 ≤ 0、公式 > 512）暂停自动保存并提示**，不提交

## 3 · >200 行分批保存（逻辑 PASS / 真实规模 NOT_TESTED）

本地**无 >200 行报价**（单张最大 67 行，552 是全部报价的行数总和）。
为真实走通多批路径，**临时把批大小降为 2**并拉长自动保存延迟：

```text
5 行编辑 → 手动保存 → "已保存 5 行（分 3 批）并重算"
服务端核对：5 行全部正确落库（3 / 101 / 43 / 75 / 26）—— 无丢失
随后完整还原：全部回到原值，总额回到 ¥127,037.66
```

**事务边界已明确并留痕**：服务端每次调用独立事务，跨批不保证原子性 →
成功批清除草稿、失败批及其后批次保留脏数据可重试、每轮重读服务端结果、
**不静默只保存前 N 行**。

- 真实 >200 行：**NOT_TESTED**（缺数据；需构造 200+ 行报价后重跑）
- 恢复生产常量：`BATCH_SIZE = QUOTE_BATCH_MAX_LINES(200)`、`AUTO_SAVE_DELAY_MS = 1200`
