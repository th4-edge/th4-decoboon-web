结论：

- `1920/1440` 三栏可用，五页主行动首屏可见。
- `1280` 时跟进、量房、谈单、签约按共享规则降为两栏，但右栏被排到整个中栏之后，主行动落入第二屏；设计页仍强行三栏，中栏仅 `318px`，内部 `scheme-cards` 宽度 `652px`，产生横向滚动和内容挤压。
- `1024` 时五页均为单栏，右栏主行动位于中栏全部内容之后；设计页主行动在 `y=2683`，页面总高 `3034px`。
- 当前小样本下未见左栏队列纵向溢出；但在 1440/1280，左侧角色导航本身可滚动，同时页面也滚动，已形成两个纵向滚动上下文。201+ 数据时左栏还会增加第三个内部滚动区。
- 设计页方案卡在 1920、1440、1280 均存在横向内部滚动（`scrollWidth=652`，容器宽度分别约 `640/444/284`）。
- 所有分辨率均未出现页面级横向溢出；问题集中在设计页栏内横向溢出。

## 7. 待我设计的 URL 参数结论

从菜单进入后会生成：

```text
/designer/design?customerId=...&activePropertyId=...&schemeId=...
```

原因不是菜单携带，而是页面 `loadDesignTasks()` 在用户未选择时自动选择首条任务，`loadCustomerWorkspace()` 再自动选择首个方案，随后 `syncQuery()` 把这组对象锚点写回 URL。该机制可用于刷新恢复，但不应在首次进入菜单时自动制造上下文；建议仅在用户显式选择后写回，菜单链接保持规范地址。

## 8. 建议修复顺序

1. **先统一查询契约**：量房、设计新增真正的 `Page` Provider；跟进改为 20 条服务端分页并下推 keyword/queue bucket；谈单、签约把过滤、排序和分页下推 SQL，再批量组装当前页。
2. **统一 App/Web 阶段资格**：设计两端都必须只接收已量房且未签约房屋；补 App 待跟进/待量房入口，或明确 App 只提供客户与项目路径，避免两个 403/缺失入口。
3. **统一一个布局壳**：统一 Header、工具栏、左队列、中工作面、右指导；1440 以上固定 `290 / minmax(0,1fr) / 290`，1280 改为两栏且把下一步移到工作面顶部，1024 使用首屏主行动条。
4. **只保留一个主行动**：中栏不再重复按钮；窄屏把同一主行动吸附到视口底部，禁止排到长内容末尾。
5. **消除多滚动**：左栏用 20 条分页替代内部长滚动；页面只保留一个纵向滚动；设计页方案卡改为栅格/纵向列表，取消横向滚动。
6. **最后统一视觉与文案**：页头间距、根内边距、列宽、按钮高度、阶段状态措辞和分页 footer。
