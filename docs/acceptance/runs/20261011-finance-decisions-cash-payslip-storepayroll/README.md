## 四、顺手修掉的两个真缺陷（**同一族：状态静默降级**）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 「我的工资条」接口返回 `Published`，页面却显示**「待发放」** | Web `enumKey()` 返回**小写** key，而映射表键写成 PascalCase（`Published`），全部落到兜底值 `?? 'pendingPayment'` | 映射表键改小写；**并去掉兜底**：未登记状态返回 `null`，页面显示「待业务确认」 |
| 2 | 「本店薪酬」工资项状态取不到（会显示「待业务确认」） | `employeePayrollItemOf` 用 `text(raw.status)` 取枚举对象 `{name,key}`，得到对象而非状态 | 改为 `enumKey(raw.status)`（取枚举 key，小写） |

**纪律**：财务场景**严禁用默认状态掩盖未知**。未登记的枚举必须显示「待业务确认」，不得 fallback 到某个真实状态——否则财务会把它当成事实。这两条已记入本轮教训。
