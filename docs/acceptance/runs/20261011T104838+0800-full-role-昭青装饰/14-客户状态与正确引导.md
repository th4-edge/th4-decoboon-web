> 本次仅财务单角色、read-only，因此本专项**只覆盖"正确引导"中与财务相关的判据**；客户状态流转需其他角色会话 → 标注 `NOT_TESTED`。

`NOT_TESTED`（财务会话内无客户阶段视图；阶段轨道/休眠恢复/终态可见性未验证）。

## 二、正确引导（本次实际结论）

| 判据 | 结果 | 证据 |
| --- | --- | --- |
| 引导是否只是正式规则的界面投影（不新增业务裁决） | ✅ 财务首页明确写"正式状态、金额、核销、成本完整性与利润全部以服务端事实为准"；资金缺口直接取服务端同名指标（待收/待付），**前端不做减法** | step01 |
| 入站队列是否来自服务端真实对象与状态 | ✅ 逾期催收逐条为真实项目与待收金额（如"合同签约款 昭青演示项目 37 · 2026-09-24 到期 待收 ¥10,675.77"） | step01 |
| **不可达/无权入口不展示** | ❌ **违反**（XA-003）：「本店薪酬」在财务菜单可见，点开即"当前账号无权执行该操作" | step04 |
| **入口语义与承载页面一致** | ❌ **违反**（XA-002）：「工人工资」打开「应付账款」页 | step05 |
| 规则未命中是否显示"待业务确认"并禁用主操作 | ✅ 「成本未完整」时利润区不显示数字并给出补齐条件说明 | step01 |
| 完成后是否显示去向 / 接棒人 | `NOT_TESTED` | 需写操作 |
| 上游未完成时下游是否阻断 | `NOT_TESTED` | 需跨角色 |
| 错误语义区分（404 vs 403） | ❌→✅ **修复后通过**（XA-004）：修复前未知路径也报「无权访问」，会误导用户去申请权限 | step07 |

## 三、本专项结论

财务端的**"给结论 + 写口径 + 不伪造"做得好**（这是财务公理的正向落地）；
**"入口一致性"是当前最集中、最影响信任的短板**——三个入口级问题（一个可见不可用、一个语义错位、一个深链接不生效）都属"承诺与实现不一致"，
本质是**跨层契约（菜单/注册表/服务端权限/页面实现）没有一处统一校验**。
