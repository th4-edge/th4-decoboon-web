# 角色评价（Finance · 财务 吴濛濛）

> 本次仅 Finance 单角色（用户指定"财务 web 页面"）。沉浸体验者＝财务本人视角；审计员视角另起。

## 一、沉浸式体验（财务第一视角）

**我登录后看到什么**：顶栏「财务 · Company」，落地「财务工作台」。第一眼是——
> 「第一眼先看账上还有多少钱（现金余额）。期初未承接时余额只作过程参考；正式状态、金额、核销、成本完整性与利润全部以服务端事实为准。」
> **当前账面现金余额 ¥45,605.56**（标注"期初未承接，余额为过程参考"）

作为财务，**这正是我每天开工要先看的东西**：账上还有多少钱、有多少该收、有多少该付。

**我接着做了什么 / 卡在哪**：

| 我想做的事 | 我看到/遇到 | 判断 |
| --- | --- | --- |
| 看今天要收的钱 | 首屏「待收工程款 ¥732,550.36，逾期 ¥365,482.57 · 回款率 9.2%」，下接「逾期催收」逐条列出项目与待收金额、带「登记收款」 | ✅ **结论在前、动作在后**，符合财务思维（先看风险再动手） |
| 看资金闭环是否对得上 | 「资金闭环」区：客户侧 应收 ¥806,921.79 → 待收 ¥732,550.36 → 已收 ¥74,371.43；供应商/员工侧 应付 ¥88,622.66 → 待付 ¥69,860.00 → 已付 ¥18,762.66 | ✅ 两条腿并列，缺口直接用服务端同名指标（不在前端做减法），可信 |
| 看利润 | 「项目经营结果 · **成本未完整**」，并写明"成本未完整时利润不显示，禁止伪利润" | ✅ 宁可不说，也不给错数（符合财务公理） |
| 查历史月份薪酬 | 点「薪酬工作台」，想回看 9 月 → 地址栏写 2026-09 被改回 2026-10 | ❌ **卡住**（XA-005） |
| 看本店薪酬 | 点「本店薪酬」→ 直接弹「当前账号无权执行该操作」 | ❌ **卡住且困惑**：菜单给了我，又说我没权限（XA-003） |
| 看工人工资 | 点「工人工资」→ 打开的却是「应付账款」页 | ❌ **困惑**：我要看的是工人工资，标题却是应付账款（XA-002） |
| 随手刷新一下页面 | **被弹回登录页** | ❌ **严重打断**（XA-001，已修） |

**一句话感受**：首屏与资金闭环区**很像财务会用的工具**（结论＋口径＋动作都在），但**横向的导航与权限一致性**拖后腿——
三个菜单项（工人工资 / 本店薪酬 / 薪酬工作台周期）各有各的“承诺与实现不一致”。

## 二、审计员视角（企业协同与产品价值）

**真实价值（有证据）**：

1. **把"账上还有多少钱"变成第一答案**，且**主动标注边界**（期初未承接 → 余额只作过程参考）。这是财务最需要的"先给结论、再给依据"。
2. **资金闭环用双条腿表达**（客户侧应收→待收→已收 / 供应商员工侧应付→待付→已付），并把缺口交给服务端同名指标，**前端不做减法**——避免了"两个页面减出两个数"的经典财务事故。
3. **利润在成本不完整时根本不显示**（"禁止伪利润"），并说明补齐条件 → 对"不制造伪利润"这条财务公理是直接支撑。
4. **逾期催收按风险排序**（逾期应收优先、临期单独提示），每条都带「登记收款」入口 → 从"看到风险"到"处理风险"只有一步。
5. 三档分辨率 4 页 × 3 档**全部无横向溢出**（`scrollWidth === innerWidth`），控制台 **18 个页面 0 error**。

**协同断点（有证据）**：

1. **权限与菜单不一致**（XA-003）：菜单存在 = 承诺可用，但服务端按门店范围拒绝财务 → 这是**跨层契约不一致**，不是单纯 UI 问题。
2. **入口语义与页面实现不一致**（XA-002）：一个组件被两个语义不同的菜单项复用，且没有类型区分。
3. **深链接承诺未兑现**（XA-005）：注册表/条款写了 `period={period}`，实现只认当前月。
4. **导航错误语义**（XA-004，已修）：404 与 403 混为一谈，会让用户走错排查方向。

**对新企业/日常使用的成本判断**：首屏能干活、口径敢写明边界，这部分**上手成本低**；但"点了没用/点了不对"的入口会持续消耗信任——
财务是最容易因为"数据不对/进不去"而放弃系统的角色。
