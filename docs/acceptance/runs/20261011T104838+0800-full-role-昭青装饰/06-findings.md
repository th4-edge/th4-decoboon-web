# 发现与价值结论

> 缺陷明细见 `11-bug-ledger.md`（XA-001~005）。本文件只给**价值判断**与**整改优先级**。

## 一、最值得保留的能力（有证据）

1. **第一答案＝现金余额，且主动写边界**：「当前账面现金余额 ¥45,605.56 · 期初未承接，余额为过程参考」。
   财务每天开工第一个问题就是"账上还有多少钱"，这里直接回答，并**不把过程数伪装成结算数**。
2. **资金闭环用双条腿表达、前端不做减法**：客户侧 应收 ¥806,921.79 → 待收 ¥732,550.36 → 已收 ¥74,371.43；供应商/员工侧 应付 ¥88,622.66 → 待付 ¥69,860.00 → 已付 ¥18,762.66。
   缺口直接取服务端同名指标 → **从机制上避免了"两个页面减出两个数"**。
3. **成本不完整时利润根本不出现**（"禁止伪利润"）——把财务公理写进了界面。
4. **风险优先、动作贴身**：逾期应收 ¥365,482.57 逐条列出并各带「登记收款」，临期 7 天内单独提示。
5. **工程侧基线扎实**：18 个页面控制台 0 error；4 个关键页 × 3 档分辨率共 12 组**全部无横向溢出**。

## 二、最大的协同断点：**"承诺与实现"分散在四层，没有一处统一校验**

| 层 | 承诺 | 实现 | 结果 |
| --- | --- | --- | --- |
| 菜单 | 「本店薪酬」可用 | 服务端按门店范围拒绝财务 | **可见不可用**（XA-003） |
| 菜单 | 「工人工资」 | 复用「应付账款」组件 | **语义错位**（XA-002） |
| 契约条款/注册表 | `deepLink: /finance/payroll?period={period}`、`contextRecovery.deepLink=true` | 只认当前月 | **深链接不兑现**（XA-005） |
| 导航语义 | 404 与 403 区分 | 未知路径也报"无权访问" | **引导错误**（XA-004，已修） |

→ 四个问题**同一个形状**：某一层写了承诺，另一层没兑现，且**没有门禁校验这两层是否一致**。
现有九项 `check:*` 校验的是注册表内部一致性与静态路由可达性，**不校验"菜单项承诺的语义"与"页面/服务端实际行为"是否一致**。

## 三、最严重的问题：**刷新即掉登录（XA-001，P1）**

它是**跨全角色、跨全页面**的基础能力缺陷（非财务专属），且**门禁全绿也发现不了**：
9 项 `check:*` + `build` + `tsc` 在这两个 bug 存在时**全部通过**。

它同时证明了一件方法论上的事：**"构建成功 + 门禁全绿"与本技能要回答的问题（真实岗位能不能用）之间没有必然关系**——这正是本技能存在的理由。

## 四、建议整改顺序

| 顺序 | 事项 | 理由 |
| --- | --- | --- |
| 1 | 建立**"入口承诺 vs 实现"一致性门禁**（菜单项 → 页面语义 + 服务端权限范围） | 一次治住 XA-002/003 这一类（当前无任何门禁覆盖） |
| 2 | 收敛「本店薪酬」入口口径（移除 / 放开财务只读 / 改语义） | 财务最痛的"点开说我没权限" |
| 3 | 「工人工资」做专属过滤与标题（或下线该项） | 菜单承诺与页面不符 |
| 4 | 薪酬周期深链接：要么支持历史周期，要么去掉参数承诺 | 契约条款与实际不一致 |
| 5 | 把"刷新/直开链接保持会话"纳入**回归清单**（本次已修复，需防再犯） | P1，且门禁不覆盖 |
