## XA-20261011-001 · 刷新即掉登录（P1，已修）

- **真实用户目标**：财务正在核账，按 F5 刷新或从收藏夹直接打开 `/finance/ledger`。
- **最小复现**：浏览器登录成功（落地 `/finance/workbench`）→ 按刷新 → 落到 `/login?redirect=/finance/ledger`。
- **期望**：刷新后仍在原页面（Web 端面协议要求"深链接与刷新"可恢复）。
- **实际**：任何硬加载都被判未登录。
- **影响**：**所有角色的所有 Web 页面**（非财务专属）；刷新、收藏、直接分享链接全部失效。
- **证据**：`localStorage['decoboon-web.token']` 存在且 168 字符；用该 token 直连 `auth/session/info` 返回 **200 / success:true / 角色 Finance** → **token 有效，是前端未做启动水合**。
- **根因（已定位）**：`stores/session.ts` 中 `isAuthenticated = Boolean(token && profile)`，而 `profile` 只在内存；
  `2026-10-11` 按角色静态化重写 `core/router/index.ts` 时，**丢掉了原守卫里的 `if (hasToken && !session.ready) await session.loadProfile()` 启动水合块**（`git show HEAD:src/core/router/index.ts` 第 458 行可见原逻辑）。
- **修复**：在守卫最前恢复水合（有 token 且 `!ready` → `loadProfile()`，失败则 `clear()`）。
- **回归**：登录 → 刷新 → 仍停 `/finance/workbench`；`/finance/ledger` 刷新保持。
- **教训**：9 项门禁 + `build` + `tsc` 全绿**都不会**发现它；只有真实浏览器刷新能发现（与用户"必须通过浏览器访问"的要求直接相关）。

## XA-20261011-004 · 404 被伪装成「无权访问」（P2，已修）

- **最小复现**：登录后直开 `/totally-unknown-page` → 页面显示 **「无权访问该页面」**（而不是 404）。
- **期望**：不存在的路径 → 404「页面不存在」；只有**属于别的角色**的已知路径才是「无权访问」。
- **实际**：全站未知路径都判越权 → 用户会以为自己权限不足，去申请权限，而实际是路径错了（正确引导失效）。
- **根因（已定位，同为上述重写的自引入问题）**：`isKnownToSomeRole()` 用**前缀匹配**且已知集合包含根路径 `/` 与 catch-all 模式 `/:pathMatch(.*)*`，
  导致"任意路径都算已知"。
- **修复**：改为**整段全匹配**（段数相等 + 动态段通配），并排除根路径与 catch-all 模式。
- **回归**：`/totally-unknown-page`·`/nope` → 「页面不存在」；`/designer/projects`·`/pm/workbench`·`/workbench/my-customers` → 「无权访问」（保持正确）；`/designer/projects/9999999`·`/finance/ledger/extra` → 「页面不存在」。

## XA-20261011-003 · 「本店薪酬」入口可见但无权（P1，未修）

- **最小复现**：财务登录 → 侧栏「薪酬 → 本店薪酬」→ 页面标题「本店薪酬」，随即出现 alert **「当前账号无权执行该操作 重新加载」**，数据 0 条。
- **期望**：要么不显示（不可达/无权入口不展示，`EXP-013`/`EXP-021`），要么财务可只读查看。
- **实际**：入口在菜单里，点开报无权 —— **点了没用的入口**。
- **交叉核验**：该页文案自称"数据范围由服务端按门店裁决"，而财务数据范围是 `Company` → 与服务端门店范围门禁冲突。
- **建议（不属本技能裁决）**：由一个口径拍板：① 财务移除该菜单项；② 或服务端对 `Finance` 放开只读门店范围；③ 或改标题与入口语义为"门店薪酬（无权限）"并提前隐藏。
- **证据**：`raw/screenshots/step04_store-payroll-no-permission_finance_1440x900_after.png`（截图）+ 本次 DOM 文本记录。

## XA-20261011-002 · 「工人工资」→ 打开「应付账款」（P2，未修）

- **最小复现**：侧栏「资金收付 → 工人工资」→ 页面 H1 = **「应付账款」**，与 `/finance/payables` 完全同页（同为 11 行数据）。
- **交叉核验**：`src/roles/routes.ts` 中 `fnSalaries: leaf('salaries', …, () => import('@/views/finance/FinancePayablesView.vue'), '工人工资')` —— **同一组件复用，无类型区分**。
- **影响**：菜单承诺与页面语义不一致，用户无法确认"工人工资"到底在哪看。
- **建议**：为该入口做工人工资专属过滤/标题（`?type=salary` 已在应付页提供应付类型过滤能力的话优先复用），或下线该菜单项。

## XA-20261011-005 · 薪酬工作台周期深链接不生效（P2，未修）

- **最小复现**：直开 `/finance/payroll?period=2026-09` → URL **立即**变为 `?period=2026-10`，页面也只显示 2026-10。
- **期望**：参数被消费（历史周期可刷新恢复），或明确拒绝并提示"仅支持当前周期"。
- **交叉核验**：`WEB-工作台契约条款` 声称 `deepLink: /finance/payroll?period={period}` 且 `contextRecovery.deepLink=true` → 当前实现与条款不一致。
- **说明**：若业务上薪酬工作台**只服务当前周期**，则应去掉 URL 参数承诺并写明；否则应支持历史周期。
