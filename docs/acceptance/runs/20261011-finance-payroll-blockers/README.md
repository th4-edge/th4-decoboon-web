## 一、问题（为什么这不是"加个提示"）

App 在工资单确认前就逐项校验并渲染**阻断清单 + 可执行下一步**（`sheet-detail.vue`，依据 `DEC-046 / BR-038`）。
Web 此前只是**直接调用 `payroll/sheet/update`（确认）**，失败才弹一句错误——财务看不到「为什么不能确认、我该先做什么」，在发薪月每次失败都是一次来回沟通。

## 二、改动

`src/views/finance/FinanceEmployeeSalariesView.vue`（纯前端，未改后端、未改权限、未改口径）：

1. 新增**确认前置阻断清单** `blockers`（对齐 App 三条硬前置）：
   - 无工资项 → 「该月没有工资项：请检查薪酬方案生效期，或重新生成工资单草稿」+「重新生成草稿」；
   - 考勤未确认（`!attendanceComplete`）→ 「考勤未确认：确认全部员工月度考勤后才能确认工资单」+「去确认考勤」；
   - 存在实发为负的工资项（`netAmount < 0`）→ 「需人工处理后才能确认」+「查看工资项明细」。
2. 新增**非阻断提示** `nonBlockingNotices`：提成未结清（`!commissionComplete`）时明确「提成与工资独立结算、独立发放，**不影响本次工资确认**」——避免财务误停整条发薪流程（App 同口径）。
3. 阻断存在时「确认工资单」置灰，并给出 tooltip 说明；其余合法动作（员工发放等）不受影响。
4. `load()` 后新增 `refreshSelected()`：确认考勤等外部动作会改变工资单完整性标记，按 `reloadScopes` 回读工资单事实，不用旧值判断。
