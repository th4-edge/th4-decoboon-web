## 一、**边界不靠裁决：从事实推导**（本轮关键）

原本我认为这一页要先请你拍"成本/毛利展示边界"。逐条核实后端事实后发现**不需要裁决**：

1. **接口本身不含成本/毛利**：`statistic/store/report` 返回 38 个字段（客户/报价/项目/任务/成员计数、报价金额、签约额、三个接受率、设计师业绩与最近项目/客户），**没有成本、毛利，也没有成本完整性标记**；
2. **唯一带成本的字段在明细里**：`recentProjects[].cost`（来自 `Project` 白名单）——但该列表**没有成本完整性标记**；
3. **若展示它会破坏两条既有规则**：`BR-003` 明确「采购执行价不得被解释为项目综合成本」，且**成本不完整时利润必须为空**（无完整性标记就无法判断）→ 展示 `cost` 等于让页面暗示一个不可靠的利润依据；
4. 因此结论：**本页不展示任何成本字段**，并在页面写明「如需展示，需后端先提供成本完整性投影，再按 `BR-003` 定边界」。

> 也就是说：**边界是"接口没给 + 给了也不能用"推出来的，不是我拍的，也不是你要拍的。** 这页因此不必等待裁决。

页面结构（对齐店长 S0 公理 2「要结论 + 可干预动作」）：

1. **今天先看这几项**（可干预）：未指派设计师 / 待客户决策报价 / 待安排量房 / 任务待办；
2. **金额区**：本店签约额（主）+ 报价金额 + 三个接受率（最终/首版/转化）；
3. **本店四类事实**：客户 / 报价 / 项目 / 成员构成；
4. **设计师业绩表**：客户 / 待量房 / 报价 / 签约额 / 在管项目 / 任务待办 / 最终接受率；
5. **最近项目 / 最近客户**（只读，**不展示成本**）。

**口径纪律**：状态与来源一律使用**服务端返回的中文名**（`status.name`），前端**不做本地映射**；金额与计数全部取服务端字段，**无任何前端计算**。
