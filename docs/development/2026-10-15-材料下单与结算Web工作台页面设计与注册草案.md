# 材料下单与结算 Web 工作台 · 页面设计与注册草案（材料员 / 财务）

> 日期：2026-10-15 ｜ 状态：**三项业务裁决已定（2026-10-15），可进入实施；注册表未落库前仍不得提交页面代码**
>
> **裁决结论**：① **材料员与财务为同一角色** → 不引入新角色，下单与结算沿用 `finance`（Boss/店长为其超集）；
> ② **月结期间按「采购下单月份」** → 与后端 `period`（`PurchaseOrder.orderedAt` 所在月份）一致，无需调整；
> ③ **结算撤销本轮做** → 已实现 `material/settlement/cancel`（迁移 119）。
> 依据：`docs/standards/*`（11 个注册/审计门禁）、业务智能体 `SOL-014` / `OBJ-008` / `BR-044` / `BR-045` / `SCN-021` / `DEC-072` / `DEC-073`
> 后端基线：主材下单作业单（迁移 117）+ 采购结算（迁移 118）+ `material/settlement/*`；App 侧已有建单/测量/请购与 Excel 导出

## 0. 为什么先出注册草案而不是直接写页面

本工程的 Web 新建页面受 11 个注册/审计门禁约束（`scripts/audit-*.mjs` 读取 `docs/standards/*.json`），
新页面必须先在注册表登记，再实现，否则 `npm run check:*` 会失败。当前基线审计全绿，因此实施顺序必须是
**先注册 → 再实现 → 再跑门禁**，不允许先写页面后补登记。

## 1. 角色与页面清单

| 页面 | 角色 | 任务 | 后端能力 |
| --- | --- | --- | --- |
| 材料请购队列（工作台） | 材料员 / 财务 | 查看待下单作业单，按供应商成单 | `material/sheet/page` |
| 作业单下单抽屉/工作区 | 财务 | 选供应商、**允许不填单价**、确认下单 | `material/sheet/order` |
| 采购结算工作台 | 财务 | 逐单/月结预演 → 确认结算 | `material/settlement/page|preview|confirm` |
| 项目成本与利润（只读引用） | 负责人 / 财务 | 成本未完整时利润显示「成本待结算」 | `project/*`（既有页面，本轮不改） |

## 2. 页面解剖（依据 `WEB-工作台设计构建规范` / `WEB-客户场景三栏工作台规范`）

- **左队列**：按「待下单 / 已下单 / 待结算 / 已结算」分组；行内展示品类、项目、行数、厂家、要求到场日、价格状态标签。
- **中工作面**：作业单明细（安装位置、型号、颜色、尺寸、数量），**不展示价格列**（作业单对厂家，`DEC-073`）。
- **右状态引导**：`NextActionPanel` 消费服务端动作视图；阻断原因（未选材 / 超净用量+损耗 / 已进入采购）。
- **唯一主行动**：队列态＝「选择供应商并下单」；结算态＝「确认结算」。

## 3. 关键口径展示规则（必须遵守）

| 场景 | 展示 | 禁止 |
| --- | --- | --- |
| 未定价下单 | 单价留空 + 标签「**成本待结算**」；应付显示「暂估」 | 用 `0` 冒充未知价；显示 0 成本利润 |
| 部分结算 | 采购单价格状态 `Mixed` → 仍显示「成本待结算」 | 提前解除暂估、显示实际毛利 |
| 结算完成 | 结算价回填 → 标签「已结算」；利润可算 | 回溯改写报价/合同成本快照；结算价写回供应商参考价 |
| 作业单详情 | 只有材料与时间、签字 | 出现单价/金额/账期/成本字段 |

## 6. 三项裁决结论（2026-10-15，已定）

1. **材料员与财务为同一角色**：页面权限沿用 `finance`（Boss/店长为其超集），**不新增角色**；`permission-policies` 按此登记。
2. **月结期间按采购下单月份**：`period`（如 `2026-10`）按 `PurchaseOrder.orderedAt` 所在月份过滤，与后端一致。
3. **结算撤销本轮做**：新增 `material/settlement/cancel`（迁移 119）。页面提供「撤销结算」入口（二次确认 + 填原因）；撤销后采购单回到「成本待结算」并可重新结算。
